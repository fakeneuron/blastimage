# BI-030.4 | schema-mismatch-banner

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-EPIC-030]]

## 🎯 Goal

Stop a version-mismatched (or corrupt) stored session from being silently swallowed by `loadSession`'s `null`: name the affected project in a banner instead of quietly bootstrapping a fresh one and leaving a dead entry in the switcher.

## ✅ Acceptance

- [ ] `loadSession` returns a discriminated result (`ok` / `absent` / `corrupt` / `unsupported-version`) instead of `Session | null`; the mismatch case carries the stored version and the project name from the index
- [ ] `loadActiveSession` and the `PersistenceAdapter` seam carry the same result through to the hook
- [ ] Mount with the active pointer at a version-mismatched session still yields a working fresh project **and** raises a banner naming the project, the stored version, and the expected one; the unreadable data is left untouched in storage
- [ ] Corrupt / invalid-shape stored JSON raises the same banner with corrupt-specific wording
- [ ] Selecting a dead switcher entry raises the banner instead of the silent `<select>` snap-back, and the current project stays active
- [ ] A genuinely absent session (first run, no pointer, storage unavailable) stays silent — the normal path grows no banner
- [ ] Tests cover the storage-level reason discrimination and both hook banner paths (mount + switch)
- [ ] `npm test`, `npx tsc --noEmit`, `npm run lint` all clean

## 🧩 Subtasks

- [ ] `lib/storage.ts` — add the `SessionLoad` union; rewrite `loadSession` to return it (name resolved from the surviving index entry); `loadActiveSession` follows
- [ ] `lib/persistence.ts` — widen `loadSession` / `loadActiveSession` on the seam to `Promise<SessionLoad>`
- [ ] `lib/useWorkspace.ts` — `unreadableSessionReason` helper; mount-time banner after the fresh bootstrap; `switchSession` banner in place of the silent `return`; adapt `generate`'s cross-session persist path to the new shape
- [ ] `lib/storage.test.ts` — load guards assert the discriminated reasons, not `null`
- [ ] `lib/useWorkspace.test.ts` — mount-over-mismatch, switch-to-dead-entry, and a silent-on-first-run control
- [ ] Verify — targeted vitest → full `npm test`, `npx tsc --noEmit`, `npm run lint`
- [ ] Doc sweep

**Discovery Notes:**

**Mechanism.** `loadSession` collapses four outcomes into one `null`, and the mount effect reads that `null` as "nothing stored yet". So an active pointer at a session the guards reject produces the first-run path: a fresh default project is created and made active. The rejected session is *not* deleted — its `blastimage:session:<id>` blob and its `blastimage:index` row both survive — so it keeps appearing in the switcher. Picking it calls `switchSession`, whose `if (!loaded) return;` is a silent no-op, and because the `<select>` is bound to `value={session.id}` it simply snaps back. Three chances to say something, none taken. Note the asymmetry this leaves: the *same* mismatch arriving through ⤒ Import has produced a named error since [[BI-022.7]] (`importSession` returns `Unsupported schema version N; this app expects M.`); only the localStorage path is mute.

**Clarifications (both answered, recommended option taken):**

1. *Surfacing scope* → **banner only**. `loadSession` gains the reason, the hook raises the existing red banner at both moments (mount-after-bootstrap, and dead-entry selection); no component changes. Marking the entry in the `<select>` was rejected as the costlier shape: `listSessions` is deliberately a lightweight metadata read (`BI-002`), and per-entry readability would mean deserializing every stored session on every list, or adding a version column to the index — re-architecting a join the epic says to leave alone.
2. *Failure set* → **mismatch + corrupt**, with distinct wording; `absent` stays silent. Both are the same silent swallow in the same function, and splitting them would leave the fix half-done for the sake of the PLAN line's literal wording.

**Deliberately not deleting anything.** The unreadable blob stays in storage and the banner says so. A future app version may know how to migrate it, and this epic's remit is visibility, not cleanup.

**Explicit assumptions:** (1) `absent` folds in "storage unavailable" (SSR / privacy mode) — both are non-events and neither should raise a banner, so no fourth state is introduced for a consumer that does not exist; (2) an index row whose session blob is missing entirely reads as `absent` and stays silent — the named drift is the *version* wall, and an id with no data behind it is not evidence of a lost project the way a rejected blob is; (3) `generate`'s cross-session persist path (`:493`) adapts to the new shape but keeps its existing silence — it can only fire if the origin session is clobbered mid-await, and growing a banner there is outside this task; (4) no migration path is written — `SCHEMA_VERSION` is still `1`, so there is nothing to migrate *from* yet.

Discovery surfaced no significant deviation → skip 🛠️.

## 🛠️ Phase 2: Execution

Replacing the contract rather than adding a parallel `loadSessionResult` keeps one load path in the module; the alternative would have left two overlapping APIs and a `null` form that silently discards exactly the information this task exists to surface. Nothing else moved — no component changed, and `generate`'s cross-session persist path adapts to the new shape while keeping its existing silence.

- [x] Implemented the minimal solution

- [x] Updated/added tests for non-trivial behavior

**Implementation Notes:**

Three source files, ~55 LOC net. `SessionLoad` has four states: `ok` / `absent` / `corrupt` / `unsupported-version`, the last two carrying the project `name` from the surviving index row (`corrupt` deliberately covers both unparseable JSON and a valid-JSON-but-wrong-shape blob, since neither is readable and both were `null` before). `unreadableSessionReason` in the hook maps a failed load to a user-facing sentence and returns `null` for the non-events, so each of the two call sites appends only its own consequence — "A new project was started; the old data is still in browser storage." at mount, "The current project is still open." on a refused switch. Two call sites, one message builder, no duplicated string assembly.

`absent` deliberately folds in "storage unavailable" (SSR / privacy mode): a fourth state would exist for no consumer, and neither case is evidence of a lost project. Nothing is deleted on a rejected load — the blob and its index row both survive, which is what keeps the entry in the switcher, and is now stated in the message rather than being an accident.
