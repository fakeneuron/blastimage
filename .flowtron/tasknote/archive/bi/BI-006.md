## 🎯 Goal

Build the feedback modal (textarea + "use as reference" checkbox + quick-approve path) opened by the review grid's feedback button, persist the feedback onto the generated image via a new pure mutator, and optionally promote the image to a keeper.

## ✅ Acceptance

- [ ] A new `FeedbackModal` component renders when the review grid's feedback button fires, pre-filled from the image's existing `FeedbackState` (text + `useAsReference`).
- [ ] Textarea edits the feedback text; a checkbox toggles `useAsReference`.
- [ ] A quick-approve path approves the image (decision → `approved`) from inside the modal.

## 🛠️ Phase 2: Execution

- [x] **Pattern survey** — looked at neighboring code for an existing pattern to extend; justified the new shape if none fits

- [x] Implemented the minimal solution

- [x] Updated/added tests for non-trivial behavior

**Implementation Notes:**

- `lib/workspace.ts` — added pure `setImageFeedback(session, taskId, imageId, feedback|null)` on the existing private `updateImage` helper; mints the `updatedAt` stamp so callers pass only `{ text, useAsReference }`. Imported `FeedbackState` type.
- `lib/useWorkspace.ts` — exposed a single action-aware `submitFeedback(taskId, imageId, feedback, action)` rather than a raw passthrough. **Why:** Save & Keep / Approve must write feedback *and* a decision atomically; two sequential hook calls would each read the same stale `session` closure and the second would clobber the first. `submitFeedback` composes `setImageFeedbackOn` → `setImageDecisionOn` on the fresh `next` session before one `commit`.
- `components/FeedbackModal.tsx` — new presentational modal: thumbnail + prompt, textarea, "use as reference" checkbox, and four buttons (Cancel · Save · Save & Keep · Approve). Local state pre-filled from `image.feedback`; Esc + backdrop click + Cancel all dismiss without persisting. Emits `onSubmit(feedback, action)` with `action ∈ {save, keep, approve}`. No prior modal pattern existed (Sidebar uses `window.prompt`), so the shape is new but follows the `ReferenceLibrary`/`ReviewGrid` idiom (foreground/background tokens, callback props).
- `components/Workspace.tsx` — owns `feedbackFor: {taskId, imageId} | null` open state, resolves the live image from session state, replaces the `onFeedback` no-op seam, and renders `<FeedbackModal>`.
- `components/ReviewGrid.tsx` — post-review polish (visual confirmation): the card's feedback button flips to `💬 Edit feedback` when feedback exists and exposes the saved text (+ "use as reference") as a `title` tooltip — chosen over an inline caption to keep cards compact (user preference).

**Deferred to BI-009 (surfaced in review, out of scope here):** the iterate / generate-again loop where a feedback-bearing image is the sole carry-forward seed (with references), approved = final, one keeper at a time to start. Captured in the `iteration-model` project memory; BI-006 only persists `FeedbackState`, it does not consume it.
