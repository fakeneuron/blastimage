# BI-002 | Local persistence layer

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-001]]

## 🎯 Goal

Implement a localStorage persistence layer plus structured export/import helpers so a full blastimage workspace (the `Session` model) survives a page refresh and can be backed up to / restored from a JSON file.

## ✅ Acceptance

- [ ] A persistence module saves and loads the root `Session` to/from localStorage, SSR-safe (no crash when `window`/`localStorage` is absent)
- [ ] Load guards on `schemaVersion` vs. `SCHEMA_VERSION` and on malformed/corrupt stored JSON, returning a clear signal rather than throwing
- [ ] Export helper serializes a `Session` to a downloadable, human-readable JSON backup
- [ ] Import helper parses + validates a JSON backup back into a `Session`, rejecting malformed input with a clear error
- [ ] `npx tsc --noEmit` and `npm run lint` pass on the new code
- [ ] Non-trivial behavior (round-trip save/load, version guard, import validation) is covered per the testing decision logged in Discovery

## 🧩 Subtasks

- [ ] Add Vitest + jsdom dev deps; add `test`/`test:run` scripts + `vitest.config.ts` (jsdom env); ensure ESLint ignores the config/test glob as needed
- [ ] Implement `lib/storage.ts` — SSR-safe storage accessor, namespaced keys, `SessionMeta` index type, CRUD (`listSessions`/`loadSession`/`saveSession`/`deleteSession`), active-session pointer (`getActiveSessionId`/`setActiveSessionId`/`loadActiveSession`), quota- and corruption-safe load/save returning result objects rather than throwing, `schemaVersion` guard on load
- [ ] Implement export/import in `lib/storage.ts` — `serializeSession` (pure JSON string), `downloadSession` (browser Blob+anchor), `importSession` with a hand-rolled `isSession` type guard returning `{ session } | { error }`
- [ ] Write `lib/storage.test.ts` — save→load round-trip, `schemaVersion` mismatch guard, corrupt-JSON guard, import rejects malformed backup, multi-session index + active pointer
- [ ] Run `npx tsc --noEmit`, `npm run lint`, and the new test suite — all clean

**Discovery Notes:**

- **Two distinct JSON shapes in the model.** `ExportManifest` (in `types.ts`) is the *approved-images* export (BI-008/009). BI-002's export/import is the *full-workspace* backup — the entire `Session`. These are different features; this task owns only the full-session backup.
- **base64 inline images** mean a `Session` can be large; localStorage has a ~5MB cap. Out of scope to solve here, but the save path should fail gracefully on quota errors rather than throw.

**Clarifying decisions (operator):**

1. **Session scope → multiple named sessions.** Storage holds an index of lightweight `SessionMeta` (`{id, name, updatedAt}`) plus per-session keys and an active-session pointer — `listSessions` / `loadSession` / `saveSession` / `deleteSession` / `get|setActiveSessionId`. (Not the simplest single-key form.)
2. **Testing → add Vitest now.** Install Vitest (+ jsdom for `localStorage`), add a `test` script, and cover the non-trivial logic. Establishes the project's test culture in this task.
3. **Import validation → hand-rolled lightweight guards.** Top-level shape/type-guard (`isSession`) checking required keys, `schemaVersion`, and array presence — no zod, no second source of truth.

**Exit-gate judgment:** Discovery surfaced a significant scope deviation — multiple-session storage restructures the API beyond the literal "save/load" line, and adding Vitest is a cross-cutting test-infra concern → **fire 🛠️**.

**Key design choices for execution:**

- Keys: `blastimage:index` (JSON `SessionMeta[]`), `blastimage:session:<id>` (full `Session` JSON), `blastimage:active` (id string). All prefixed `blastimage:`.
- `SessionMeta` is a persistence-layer index type → defined in `lib/storage.ts`, not `lib/types.ts` (surgical; keeps the core model untouched).
- `serializeSession` is pure (testable); `downloadSession` is the thin browser-only DOM wrapper around it.
- BI-002's export/import is the **full-`Session` backup** — distinct from the `ExportManifest` (approved-images export, BI-008/009), which this task does not touch.
