**Discovery Notes:**

**Design surface inventoried (HEAD `8c70e57`):**

- `lib/types.ts` — `Session` (`name`, `imagegenRoot?` optional/structural), `Iteration` (`index`, `images`, `createdAt`; **no round field** — a round is recovered from image URLs via `iterationTouchesRound` / `roundNumberFromImageUrl`).
- `lib/workspace.ts` — `renameSession`, `bindImagegenRoot`, `projectNameFromRoot` (repo folder containing `imagegen/`), `imagegenRootLabel` (last two segments), `ingestRoundBatch` → `upsertIterationForRound` (BI-043 replace-on-reload).
- `lib/storage.ts` — `isSession` is structural, so an optional `currentRound` needs no `SCHEMA_VERSION` bump (BI-047 precedent); `SessionMeta` index carries `imagegenRoot`.
- `lib/useWorkspace.ts` — `loadedRound` is `useState` (**not persisted**, reset on switch by BI-047); `availableRounds: number[]` from `imagegen.listRounds()`; `linkImagegenFolder` (L1053) already auto-names via `projectNameFromRoot`, but **only when `name === DEFAULT_SESSION_NAME && tasks.length === 0`**; `loadRound` ingests one round and sets `activeTaskId` to its first task.
- `lib/roundBatch.ts` — `RoundBatch.generatedAt` is validated but never stored; `RoundBatchTask.images[]` gives per-round counts for free.
- `components/Workspace.tsx` L57-75 — BI-026 one-shot autoload of the **latest** round only; opens `BulkReviewPane` when >1 task.
- `components/TaskDetail.tsx` L99 and `components/BulkReviewPane.tsx` L48 — both render `task.iterations.at(-1)`, i.e. the latest iteration **regardless of which round was loaded**. Loading r1 after r2 leaves r2 on screen because the upsert keeps r1 at its original position. This is the actual "can't toggle rounds" defect and the heart of `.4`.
- `components/Sidebar.tsx` L132-247 — the top block: `<select id="project-select">`, `+ New` / `Rename` via `window.prompt`, `⤓ Export` / `⤒ Import` backup (BI-022.7), `🔗 Link imagegen` (BI-046 modal), `↻ Load round` + `rN` chips (BI-024.1), then `🛠 Build` / `⇪ Import` / `+ New task` (BI-019/021.3) and `Generate All` (BI-015, disabled-with-reason per BI-031.2).
- Server: `app/api/imagegen/rounds` (lists round numbers) is the route `.3` extends; `lib/imagegenRouteGuard.test.ts` covers the route handlers from `lib/`.
- Docs naming sidebar controls: `README.md` (5 hits), `docs/REVIEW-LOOP.md`, `docs/WORKFLOW.md`, `docs/ADOPT.md` (3 each) — updated inside `.5`, not here.
- Tests naming sidebar controls: `components/Sidebar.test.tsx`, `components/Workspace.test.tsx`, `e2e/imagegen-link-load.spec.ts`.

**Best Practices Review:** the children extend established seams — `Session` optional field + structural guard (BI-047), `lib/workspace.ts` pure mutators, `ImagegenApi` injected seam for the summaries, `useWorkspace` as the single orchestration layer (BI-049: add here, no parallel hook). One deliberate dependency-direction note for `.4`: "which iteration to show for round R" belongs in `lib/workspace.ts` as a pure selector so `TaskDetail`, `BulkReviewPane` and the approve/iterate fallbacks share one definition instead of three `at(-1)` reads.

**Final Summary:**

Filed `BI-EPIC-053` (session-round-navigation) and closed its Discovery. The epic makes a project's identity and its terminal rounds legible: rounds become a persisted, toggleable view inside a project (never separate sessions), projects auto-name from their linked `imagegen/` root, every round auto-ingests, and the sidebar's action stack is triaged into a header + rounds list + tasks with a ⋯ menu.

Discovery's load-bearing finding: `TaskDetail` and `BulkReviewPane` both render `iterations.at(-1)`, so "loading" an earlier round changes nothing on screen — the round→iteration link is URL-derived and `loadedRound` is unpersisted `useState`. That defect is `.4`'s core.
