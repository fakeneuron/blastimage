# BI-019 | task-import

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[BI-014]]

## 🎯 Goal

Let adopter projects stage prompt tasks programmatically: import a JSON file (`{version, tasks: [{name, basePrompt}]}`) into the current session as fresh PromptTasks — pure lib parse/validate/merge + a sidebar file-input — complementing the existing export manifest. Driving need: spinalcord SCI-017.2's 5 composed hero prompts (and ~56 more at the SCI-017.4 full run).

## ✅ Acceptance

- [x] Pure lib function parses + validates the import JSON (clear errors on malformed input) and merges tasks into the session immutably, reusing existing factories

- [x] Import appends — never overwrites or deletes existing tasks/sessions
- [x] Unit tests cover parse/validate/merge happy path + malformed-input rejections

**Discovery Notes:**

**Existing shapes to extend (verified):**
- `lib/storage.ts` §"Export / import" already has `importSession(json): Result<Session>` — hand-rolled `isRecord`/`isSession` guards, no zod, clear error strings, version check. `parseTaskImport` is the same family and lands beside it, reusing `Result<T>` + `isRecord`.
- `lib/workspace.ts` — pure, immutable, React-free mutations; `newTask(name)` factory + `addTask(session, task)` append + private `touch()`. `importTasks(session, drafts)` follows this exactly (bulk append, single `touch`).
- `lib/useWorkspace.ts` — every mutator: pure transform → `commit()` (persist + state + error surface). Save/generation failures already flow through `error: string | null`; import parse failures reuse it (no new error channel).
- `components/ReferenceLibrary.tsx` — the file-ingestion precedent: DOM concerns (file input, FileReader, validation messaging) live in the component; pure mutations in lib. Sidebar import control mirrors this with `file.text()`.
- `components/Sidebar.tsx` header row ("Tasks" label + "+ New task" button) is the natural slot for the Import control; props wire through `Workspace.tsx` (`ws.importTasks`).

**Archive skim:** BI-002 deliberately scoped storage's import to the *full-Session backup* and noted `ExportManifest` (BI-008) as a distinct shape — a third JSON shape (task-list import) is consistent with that separation and must not be confused with either; hand-rolled-guards-over-zod is an explicit BI-002 decision to follow. BI-015 (`generateAll`) is the consumer that makes bulk import valuable (eligibility = non-empty prompt or ref). BI-017 added the 4MB generated-bytes quota warning — import adds only text, no quota concern. CORE-001.x was a quality sweep; no contract changes.

**Import JSON contract (decision):** `{"version": 1, "tasks": [{"name": string, "basePrompt": string}, …]}` — `version` must equal `1` (mirrors the schemaVersion guard), `tasks` must be a non-empty array, `name` non-empty after trim, `basePrompt` a string (empty allowed — valid in-app, just ineligible for Generate All). Rejects with specific error strings per failure, matching `importSession` tone.

**No clarifications needed.** Explicit assumptions: (1) import **appends** to the current session — never replaces tasks or creates a session (operator can `+ New` a session first); (2) no reference-image import in scope — refs stay UI-uploaded (spinalcord's prompts are text-only by design, Reference-cue excluded); (3) no dedupe/upsert by name — re-importing duplicates tasks, acceptable for v1; (4) success feedback = task list grows + first imported task selected, failures via the existing error banner.
