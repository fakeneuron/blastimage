## 🎯 Goal

Replace the `window.prompt` absolute-path paste with a server-backed folder picker — a `GET /api/imagegen/browse` directory-listing route plus a picker modal offering detected `imagegen/` shortcuts, a navigable tree, and typing a path as the fallback.

**Discovery Notes:**

**What BI-045 left behind.** It replaced the File System Access layer with localhost routes, which is why linking works in Safari and Brave at all. But FSA was also the only browser API that *yields* a path, so its replacement had to ask for one: `promptAndLinkImagegenFolder` pre-fills a `window.prompt` from `suggestRoots(cwd)` — the `imagegen/` beside the app and the one inside it — and the operator types or corrects the rest. Everything needed to do better is already server-side; only the listing verb is missing.

**Browse adds no new exposure class.** The route enumerates directories, which sounds like a widening, but the guard boundary is unchanged: `guardImagegenRequest` refuses non-loopback `Host` and cross-origin callers, and anything that clears it can already name `root=/` on `/api/imagegen/file` and read arbitrary bytes. `resolveRoot` likewise accepts any absolute path today. So the picker is discovery UI for a capability the operator already has, not a new one — which is what makes the operator's "no confinement" answer consistent rather than permissive. Confinement stays where it does real work: `resolveUnderRoot` under the *linked* root.

**Two established idioms to extend, not invent.** BI-033 replaced `window.confirm` with `DeleteTaskModal` for exactly this reason (a prompt cannot carry a third affordance); BI-039 gave every dialog `useFocusTrap`. The picker is the same move against `window.prompt`, so it copies `DeleteTaskModal`'s shape: presentational component, `role="dialog"` + `aria-modal` + `tabIndex={-1}`, backdrop click and Escape dismiss, open state owned by `components/Workspace.tsx`, and the actual link performed by `lib/useWorkspace.ts`.

**The `cancelled` status retires with the prompt.** `LinkImagegenResult` models a dismissed `window.prompt` as `{status: 'cancelled'}`, handled in `useWorkspace.linkImagegenFolder`. With a modal, cancelling is closing the dialog and never reaches the API, so that case becomes unreachable. `linkFolder` collapses to the codebase's ordinary `Result<string>` (the canonical root) and the error surfaces inline in the modal rather than in the global banner — a bad path should leave the picker open.

**Implementation Notes:**

**Unconfined by design, and it is the guard that makes that safe.** `listDirectories` takes any absolute path, `/` included — the operator's Phase 1 answer. The reason it adds no exposure is that `guardImagegenRequest` is unchanged and is the real boundary: anything that clears it can already pass `root=/` to `/api/imagegen/file` and read arbitrary bytes, and `resolveRoot` has always accepted any absolute path. Confinement stays where it does work, under the *linked* root via `resolveUnderRoot`. Verified live: cross-origin 403, rebinding `Host` 403, missing folder 400, relative path 400.

**Symlinked directories are followed, not dropped.** `entry.isDirectory()` is false for a symlink to a directory, which would have left a silent hole in the tree — exactly the kind of "where is my folder" confusion the typed path existed to work around. `isNavigableDir` stats the link before deciding. Confirmed live against a fixture: a symlink to an `imagegen/` folder lists *and* carries the recognized badge.

**Dot-directories are skipped and the typed field stays.** An `imagegen/` folder is never hidden, so filtering them keeps `~` and `/` legible; the typed-path fallback is what reaches anything the tree omits. That is the same reason the fallback is a first-class control rather than a fallback in name only.

**The listing carries absolute paths per entry.** `DirectoryEntry.path` is absolute so the modal never joins paths itself — one place (the server) decides what a path is, which is also what keeps the client free of `node:path`.
