**Discovery Notes:**

Root cause chain:
1. Provider restore is async; first paint can have `handleRef.current === null` and `linked === false`.
2. Early `resolveDisplayUrl(imagegen:…)` hits `if (!root) return url` and returns the raw scheme.
3. Callback identity never changes (`useCallback([])`), so `ResolvedImage`'s effect does not re-fire when restore completes.
4. Result: stuck raw `imagegen:` src for the life of the mount.

Minimal fix sketch: `const { resolveDisplayUrl, linked } = useImagegen();` + add `linked` to the effect dependency array. When restore (or picker link) flips `linked` to true, effect re-runs and successfully mints a blob URL.

Flip test: invert expectations of the quirk block (expect a read + `blob:…` src after restore settles); rewrite the comment as a contract. Header note about `<Linked>` can stay as app-mirror convenience but should drop "required because of the quirk" language.
