# BI-045 | imagegen-server-adapter

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-024.1]] · [[BI-029.2]] · [[BI-042.2]]

## 🎯 Goal

Make the imagegen folder link work in every browser — including Safari and Brave, which have no File System Access API — by replacing the FSA layer with localhost Next API routes over Node `fs` behind the unchanged `ImagegenApi` seam.

## ✅ Acceptance

- [x] Clicking **🔗 Link imagegen** in Safari and Brave links the folder and loads a round — no "This browser does not support linking an imagegen folder." reachable anywhere on the imagegen path

- [x] All six imagegen operations work through the API routes: round listing, `batch.json` read, image display bytes, `selection.json` merge-write, approved promote/unpromote, and approved-conflict detection

**Discovery Notes:**

**Root cause.** `pickAndLinkImagegenFolder` (`lib/imagegenFs.ts:163`) feature-detects `window.showDirectoryPicker` and returns the red-banner error when it is absent. WebKit has never implemented the File System Access API, and Brave ships it disabled by default behind `brave://flags/#file-system-access-api` — so the whole terminal review loop is Chromium-and-Edge-only today, which no doc states.

**Why the seam makes this cheap.** All twelve FSA-dependent operations already sit behind `ImagegenApi`; `useWorkspace` never touches a `FileSystemDirectoryHandle` and `lib/storage.ts` deliberately never imports the FSA layer (BI-029.2 fixed the dependency direction). Swapping the provider's internals therefore reaches no consumer.

**Blob machinery goes inert, not away.** BI-042.2 / BI-042.4 built a refcounted blob-URL cache with an eviction epoch because FSA hands back `File` objects that must be `URL.createObjectURL`'d. A `/api/imagegen/file?path=…` URL is directly renderable, so `resolveDisplayUrl` stops minting blob URLs. Keeping `blobEpoch` and `retainDisplayUrl` as interface members (epoch becomes the cache-buster query param; retain becomes the no-op `NOOP_IMAGEGEN` already ships) leaves `components/ResolvedImage.tsx` untouched — its `displaySrc.startsWith('blob:')` guard self-disables. The cache internals themselves are deleted rather than left dead.

**BI-028 is precedent, not obstacle.** It removed the *cloud* Supabase stack, reasoning that Neon/R2 "require server-side credentials plus an auth story." A localhost `fs` route requires neither: no credential is exposed to the browser, nothing is deployed, and `CLAUDE.md` already names API routes as part of the stack. The localStorage-only persistence contract is untouched — session state does not move.

**BI-024.1 is superseded on one factual claim** — its Acceptance reads "User can link the host repo's `imagegen/` folder (Chromium FSA)". That stops being true at this task's closure, so it earns the ⚠️ pointer at Phase 4.

**Implementation Notes:**

**Stateless root, not server-held.** The root rides on every request instead of living in a module-level variable set at link time. Next hot-reloads route modules in dev, so server-side module state would vanish mid-session; passing it keeps the exchange restart-proof. It widens nothing — the routes confine every path under whatever root they are handed, and refuse cross-origin callers outright.

**Two vestigial interface members, kept deliberately.** `retainDisplayUrl` and `blobEpoch` stay on `ImagegenApi` even though there is no longer an object URL to pin. `retainDisplayUrl` becomes a no-op (the shape `NOOP_IMAGEGEN` already shipped), and `blobEpoch` is spent on HTTP cache-busting instead of `URL.revokeObjectURL` — a round rerun in the terminal rewrites files under an unchanged URL, so the `v=` parameter is what makes the browser refetch. Net effect: `components/ResolvedImage.tsx` and `lib/useWorkspace.ts` needed no rework at all. The blob cache internals (LRU eviction, refcounted holds, per-round invalidation) were deleted rather than left dead.

**Canonical-root precondition.** Containment is a prefix comparison, so every entry point takes `resolveRoot`'s `realpath` output. Surfaced by the test fixture: macOS `/var` is a symlink to `/private/var`, and a raw `mkdtemp` path failed every check. Documented in the module header and matched in the fixture — production already satisfies it, since `rootFrom` runs `resolveRoot` first.

**Two forbidden-header traps in the guard tests.** `new Request(url, {headers})` silently drops `Host` and every `Sec-*` name, so a fixture built that way asserts behaviour on headers the guard never received. The guard now reads the host from the `Host` header *or* `req.url` (Next builds it from the same header), and the tests hand it a request-shaped literal with a bare `Headers`, which carries no such guard.

**Final Summary:**

Linking the `imagegen/` folder now works in every browser. It previously used the File System Access API, which only Chromium ships — Safari has never implemented it and Brave disables it by default — so clicking **🔗 Link imagegen** in either produced a red "This browser does not support…" banner and the whole terminal review loop was unreachable. blastimage already runs on localhost behind its own Next server, so the filesystem work moved there: six API routes over Node `fs`, reached through client wrappers that keep the exact `ImagegenApi` the app already consumed.

**Changed** — 4 new lib modules (`imagegenServerFs` 289 ln, `imagegenClient` 218 ln, `imagegenRoute` 68 ln, `imagegenGuard` 71 ln) + 6 route files (~180 ln); `lib/ImagegenContext.tsx` rewritten (330 → 222 ln); `lib/imageBlob.ts` retyped; `lib/imagegenFs.ts` (462 ln) and `lib/imagegenFs.test.ts` (325 ln) deleted. Consumers untouched: `components/ResolvedImage.tsx` and `lib/useWorkspace.ts` needed no rework beyond one import path, because the interface did not move.

**Verified** — `npm test` 444 passed across 26 files (from 404/24); `npx tsc --noEmit`, `npm run lint`, and `npm run build` all clean, with the six routes registering as dynamic handlers. Live-exercised against the dev server and a scratch fixture: link, list, read, file bytes, selection write, promote/conflict/unpromote all correct, and all four guards refuse (cross-origin 403, `../` traversal 400, symlink escape 400, rebinding host 403). **Refactors** — one taken: `resolveImageBlob`'s `root` retyped rather than removed, preserving BI-029.2's dependency direction. One deferred: `exportManifestToFolder` keeps its own Chromium-only picker (`lib/storage.ts:459`), which already degrades to a download bundle elsewhere.

**Maintainability** — one filesystem implementation instead of a browser API plus a fallback, one browser story instead of two, and the confinement/origin rules concentrated in two small modules every route funnels through. The blob-URL cache, its LRU eviction, refcounted holds, and IndexedDB handle persistence are gone; `blobEpoch` survives as an HTTP cache-buster, so BI-042.2's staleness contract still holds with far less machinery behind it.
