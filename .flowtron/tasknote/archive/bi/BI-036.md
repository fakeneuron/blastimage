**Implementation Notes:**

Three changes, all mechanical:

1. `tsconfig.json` — added `"noUncheckedIndexedAccess": true` beside `strict` (+1 line).
2. `lib/imagegenFs.ts:214,216` — `parts[i]!` / `parts[parts.length - 1]!` in `readImagegenFile`, byte-identical to the sibling writer's existing narrowing.
3. 73 test lines across 4 files — `!` inserted at each index read.

The test edits were applied by a scratchpad script driven by **tsc's own error line list**, not by a repo-wide regex: the script read the `(file, line)` pairs straight from the compiler and rewrote only those lines (`]. → ]!.`, plus `fn()[n] → fn()[n]!` for the five `fireEvent(...)` argument positions). That kept the blast radius provably equal to the error set — the script logs a `NO-OP` for any targeted line it fails to change, and it reported none. The full added-line diff was then read back and eyeballed: every insertion sits on an array-index read, no double-`!`, no semantic edits.
