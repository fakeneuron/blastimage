# BI-029.3 | export-imagegen-regression

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-EPIC-029]]

## 🎯 Goal

Put executable regression coverage on the three byte-consuming export paths (`exportManifestToFolder`, `downloadManifestBundle`, `downloadReviewSheet`) driven with real `imagegen:` URLs through the real `resolveImageBlob`, so the adopter-mode export lands every image with zero failures — and so a future consumer that bypasses the seam fails a test instead of shipping silently.

## ✅ Acceptance

- [ ] All three export entry points, exercised with `imagegen:` manifest URLs through the **real** `resolveImageBlob` bound to a fake linked root, report **zero** failures and land every approved image.
- [ ] The suite is a genuine guard: `fetch` is asserted un-called on the `imagegen:` path, and a counter-case proves a fetch-only resolver (the pre-[[BI-029.2]] behaviour) fails every image on the same manifest.
- [ ] The review sheet embeds real on-disk bytes as `data:` URLs rather than the "image unavailable" placeholder.
- [ ] An unlinked folder still degrades into the counted-failure contract ([[BI-021.4]]) — `manifest.json` / `review.html` still land, nothing throws.
- [ ] `npx tsc --noEmit`, `npm run lint`, and `npm test` all pass.

## 🧩 Subtasks

- [ ] Unlinked-root case: resolver bound to `null` → `manifest.json` still written, `failedImages` equals the approved count, no throw.
- [ ] Verify: `npx tsc --noEmit`, `npm run lint`, `npm test`.

**Discovery Notes:**

The epic's bug was invisible not because the export code was untested but because the
tests and the bug lived on opposite sides of a stub. `fetch` was stubbed globally,
every manifest URL was `https:`, and the stub happily answered — so the suites proved
"export encodes correctly given resolvable bytes" while the production question was
"are these bytes resolvable at all". The fix for that class of blind spot is to drive
the real resolver with the real URL scheme, which is exactly what the [[BI-029.2]] seam
now makes possible in a unit test (root injected as an argument, no React, no FSA
runtime).

Two assertions carry most of the regression value:

- **`fetch` un-called** on the `imagegen:` path — the pre-seam code called it and
  failed; any future code that reintroduces a bare fetch trips this.
- **Filename extension derived from the on-disk blob's mime** (`image/jpeg` → `.jpg`) —
  proves the bytes actually travelled from the fake root through
  `approvedImageFilename`, not from a placeholder or an empty blob.
