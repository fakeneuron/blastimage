# BI-034.2 | relax-next-pin

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-EPIC-034]]

## 🎯 Goal

Move `next` off its exact `15.5.19` pin to `^15.5.23` so the repo picks up the security backport that clears the four high-severity advisories, and confirm all four gates stay green.

## ⚡ Notes

**Relevance:** Proceed — the PLAN line's premise holds at HEAD. `package.json:15` is still exactly `"next": "15.5.19"`, `npm audit --omit=dev` still reports 4 high advisories, and `15.5.23` is published and carries npm's `backport` dist-tag (i.e. it *is* the 15.x security-maintenance release, not a feature bump).

**Best Practices Review:** No abstraction or dependency-direction concern — this is a manifest edit plus a lockfile refresh. One in-scope widening beyond the literal PLAN wording: `eslint-config-next` (`package.json:28`) is pinned to the same exact `15.5.19`. Vercel releases it in lockstep with `next`, so floating one and freezing the other creates a skew where the lint config and the framework disagree about their own version. Moved both to `^15.5.23` for coherence — flagged rather than done silently. Deferred: no other dependency touched, and `npm outdated`'s major-version candidates (Next 16, eslint 10, React 19.2) stay out of scope per BI-EPIC-034's won't-fix.

**Drift check:** No drift. `package.json:15` = `"next": "15.5.19"` and `:28` = `"eslint-config-next": "15.5.19"`, exactly as the PLAN line cites. `npm view next@'>=15.5.19 <16'` confirms `15.5.20/21/22/23` all exist, so `^15.5.23` resolves within the 15.5 line with no major jump.

**Archive skim:** No prior tasknote touches dependency version pinning. Nearest hits: `archive/core/CORE-001.4.md:81` (edited `package.json` *scripts* only, and recorded "No CI configs in repo" — CI arrived later, 2026-07-01); `archive/bi/BI-031.4.md` (grepped `package.json` while removing the dead `BUILD_TARGET` branch, but changed nothing in it). No precedent constrains this edit.

**Pattern survey:** The repo's other dependency ranges already use caret form (`"^3"`, `"^4"`, `"^5"`, `"^20"`, `"^19"` throughout `devDependencies`). The two exact Next pins were the outliers; moving them to `^` conforms them to the file's own established shape rather than introducing a new one.

**Implementation:** `package.json:15` `"next": "15.5.19"` → `"^15.5.23"`; `:28` `"eslint-config-next": "15.5.19"` → `"^15.5.23"` (lockstep rationale above). `npm install` changed 5 packages; both resolve to `15.5.23`. No source file touched.

⚠️ **The bump does not clear `npm audit` to zero, and BI-EPIC-034's filing premise was wrong about that.** What it *did* clear is real but narrower than filed: `next`'s own **8 high advisories** (Server Actions DoS + SSRF, response-body cache confusion ×2, unbounded Edge Server Action payload, rewrites SSRF, Image Optimization SVG DoS, unauthenticated Server Function endpoint disclosure) are gone — `next`'s `via:` list is now `[postcss, sharp]` only, i.e. nothing in Next's own code. The residual 4 flagged packages are `nanoid`, `postcss`, `sharp`, and `next`-by-association, all bundled inside the Next 15 dependency tree, and npm reports their only fix as `next@16.3.0` (`isSemVerMajor: true`) — which BI-EPIC-034's Theme B won't-fix explicitly excludes. `npm audit fix --dry-run` (non-breaking) clears none of them.

**Downstream impact on [[BI-034.3]]:** as filed, `npm audit --omit=dev --audit-level=high` would fail CI on its first run. `.3` must own the resolution — options are gate at `--audit-level=critical` (0 today), pin `overrides` for `postcss`/`sharp` inside the Next tree, or baseline-diff the known 4. Not decided here; flagged for `.3` rather than silently pre-empted.

Reachability context for that decision: `sharp` is Next's image-optimization dependency and `grep -rn "next/image" app components lib` returns nothing (the app renders raw `<img>` via `components/ResolvedImage.tsx` with an eslint-disable), so it is not in this app's runtime path. `postcss` is build-time (Tailwind). `nanoid` arrives transitively under both `postcss` copies. Frontend-only, no server, no deploy target since BI-028.

**Verification:** lint ✅ · typecheck ✅ · 213 tests / 15 files ✅ · `next build` ✅ (5 static pages, 134 kB first load).

## ✅ Recap

Moved both Next pins off exact `15.5.19` to `^15.5.23` (`package.json:15`, `:28`), refreshed the lockfile (5 packages changed), and confirmed all four gates green. Two files changed plus the lockfile; no source touched.

Two things a later `/ft-audit` pass should know. First, `eslint-config-next` was bumped alongside `next` even though the PLAN line named only `next` — Vercel ships them in lockstep and a floating framework against a frozen lint config is a skew waiting to happen; the caret form also conforms both to the shape every other dependency in the file already uses. Second and more load-bearing: the epic's premise that this patch clears the advisories is **half true**, and the correction is recorded in Implementation above — Next's own 8 advisories are gone, but 4 packages remain flagged via Next 15's bundled `postcss`/`sharp`, fixable only by the Next 16 major that Theme B rules out. That lands squarely on [[BI-034.3]]'s design and is flagged there rather than worked around here.

Maintainability effect: net positive and low-risk. The repo can now take 15.5.x patches without a manifest edit, which is the actual point of the epic; the residual advisory floor is a known, documented, unreachable-in-this-app quantity rather than an unmonitored surface.
