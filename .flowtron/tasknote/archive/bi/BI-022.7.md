# BI-022.7 | session-importer

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[BI-EPIC-022]] [[BI-022.1]] [[BI-022.3]] [[BI-022.4]]

## 🎯 Goal

Wire the full-session **backup export** + **import** the app currently lacks: an "Export" that downloads a workspace as a backup JSON, and an "Import" that lands an existing local session into the current store as a fresh copy — in hosted mode the [[BI-022.4]] adapter re-hosts its inline images to buckets automatically on save, making this the local→cloud migration on-ramp.

## ✅ Acceptance

- [ ] A pure `cloneSessionWithNewIds` re-ids the whole tree (session + refs + tasks + iterations + images) and rewrites internal references (`activeRefImageIds`, `refImageIds`, `primaryRefImageId`), so an imported backup never PK-collides with an existing account session
- [ ] `useWorkspace` exposes `exportSession()` (downloads the current session as a backup `.json` via the existing `downloadSession`) and `importSessionBackup(json)` (validate via existing `importSession` → clone with fresh ids → save through the seam → switch to it)
- [ ] Both controls are available in **local and hosted** mode (no gating); in hosted mode the imported session's images land in storage buckets via the `.4` adapter (no importer-side upload code — the seam handles it)
- [ ] Sidebar Project section gets Export + Import buttons (Import via a hidden file input, mirroring the task-import precedent); parse/validation failures surface via `UseWorkspace.error`
- [ ] Pure `cloneSessionWithNewIds` unit-tested (ids change, references remapped consistently, content preserved); `importSessionBackup` covered in `useWorkspace.test.ts` (local mode)
- [ ] Local mode behaves as before for everything else; `tsc` + `eslint` clean on changed files
- [ ] Visual confirmation of the Export/Import controls
- [ ] Doc-drift sweep at closure
