# blastimage — CLAUDE.md

## Project

Local Next.js application for coordinated AI image generation workflows. Users define prompt tasks, attach reference photos, generate batches with Grok Imagine, review and iterate, then export approved images with a JSON provenance manifest. Two mutually exclusive generation modes: **Adopter mode** (BI-EPIC-024) — generation runs in a Grok Build terminal session via `/blast-generate` and `/blast-iterate`; the frontend is viewer/selector only — see `docs/REVIEW-LOOP.md`. **In-app mode** — blastimage runs directly inside a Grok Build session with the provider bridge wired, so generation happens in-browser — see `docs/GROK-AGENT.md`.

## Stack

- **Framework:** Next.js 16 (App Router, TypeScript)
- **State:** localStorage only (frontend-only; no accounts, no cloud project). The old optional Supabase hosted mode was removed in BI-028; keep `lib/persistence.ts` as the async seam for a future server-backed Neon + Cloudflare R2 adapter, but do not add browser-exposed database/storage credentials. The one server surface is `app/api/imagegen/` (BI-045) — localhost-only routes over Node `fs` that read and write the linked `imagegen/` folder, carrying no credentials and confining every path under the linked root. The exception is `browse` (BI-046), which lists directories so the picker can *find* a root and is therefore unconfined by design; `lib/imagegenGuard.ts` is what bounds it. Which folder is linked is a property of the **project**, not the app (BI-047): `Session.imagegenRoot` is the root of record, `lib/useWorkspace.ts` points the live link at it on every mount/switch/create, and `lib/ImagegenContext.tsx` only serves whatever it is pointed at — the invariant that keeps a project's root-relative `imagegen:` URLs and its `selection.json`/`approved/` writes aimed at the repo they came from.
- **Module layout:** the pure/hook split established in BI-003 and re-applied by every task since — React-free immutable `Session` mutations in `lib/workspace.ts`, DOM/`fs`/FSA writes in `lib/storage.ts` + `lib/imagegenServerFs.ts`, injected seams (`PersistenceAdapter`, `ImagegenApi`), presentational components — leaves `lib/useWorkspace.ts` as the single orchestration layer that owns React state, the `commit()` persist-and-surface path, user-facing strings, and `window.confirm`. **BI-049 surveyed splitting it and decided against it: it stays whole.** It is the largest source file (1164 L) but at 1.68x `lib/storage.ts` (694 L) it is not the outlier the 2026-08-30 repo audit claimed (that audit's "2.7x" and "40-member interface" figures are both wrong — measured 1.68x and 42). 26 of its 33 functions close over one hub (`session`/`sessionRef` + `commit` + `setError`; `commit` alone has 17 callers), so a sub-hook split would thread a five-member core object through 4-5 files; only ~80 L of its 820 code lines are genuinely detachable; and its one consumer (`components/Workspace.tsx`) re-merges everything into a single `ws` object anyway, so the 42-member surface survives any split. Add new orchestration here rather than opening a parallel hook — and re-open the question only on a real change of shape (a second consumer, or the hub itself fragmenting), not on line count.
- **Target API:** Grok Imagine via an agent-installed provider bridge (`globalThis.__grokImagineProvider`); see `docs/GROK-AGENT.md`. Adopter submodule installs use the terminal review loop instead (`docs/REVIEW-LOOP.md`, `docs/ADOPT.md` §5.1).
- **Dev port:** `next dev -p 3003`
- **Type safety:** `strict` plus `noUncheckedIndexedAccess` (BI-036), so every array/record index read is `T | undefined`. Narrow it — a guard, `?.`, or a non-null assertion where the surrounding code already proves the index exists (the prevailing style in tests and in `lib/imagegenUrl.ts`'s regex captures).
- **Testing:** vitest + happy-dom; `npm test`. Tests live beside their source as `{lib,components}/**/*.test.{ts,tsx}` — component tests were unrunnable-by-config until TEST-001.2 widened the glob. The glob still excludes `app/`, so the suite covering the route handlers lives in `lib/` and discovers its subjects from the filesystem instead (`lib/imagegenRouteGuard.test.ts`, TEST-004.3) — moving it beside the routes would silently stop running it. `globals: true` is off, so import test functions explicitly and wire `afterEach(cleanup)` by hand. Prefer real seams and `vi.stubGlobal` over module mocks; `vi.mock` is reserved for components with no injection point (see `components/Workspace.test.tsx`).
