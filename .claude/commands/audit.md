---
description: Parameterized principal-engineer audit — `/ft-audit <domain> [scope]` runs a domain's passes, capped findings, writes prioritized tickets to `.flowtron/PLAN.md`. Domains: general (default) · backend · frontend · security · performance · docs · structure · context. Stack-neutral scaffold; adopters fork to customize rubric and verification gates.
---

Invoke the `ft-audit` skill (in a forked install, your fork's local name — e.g. `audit`). The skill resolves the domain from the first `$ARGUMENTS` token (`general`/`backend`/`frontend`/`security`/`performance`/`docs`/`structure`/`context`; any other first token falls back to domain `general` with the whole argument string as scope), loads that domain's `passes/<domain>.md` pass definitions, resolves scope (`all` / path / `last-commit` / `staged`), loads the project rubric, runs verification gates, walks the domain's passes in order (five for every domain but `context`, which declares six) capped at 5 findings each unless the pass file sets a tighter cap, presents Summary + Exploratory Insights + Proposed tasks + Questions, then — after write-step confirmation — writes the agreed tickets into `.flowtron/PLAN.md` with `Surfaced by <slug> YYYY-MM-DD (Finding #N, <severity>)` attribution and auto-commits (`chore: audit file tickets — <domain>`) per `SPEC/plan-filing.md` §"Filing commits". Source files are not modified except via the §5 trivial-fix carve-out — other fixes happen in separate `/ft-task` cycles.

This skill is **stack-neutral and meant to be forked**, not symlinked from the flowtron submodule. Fork the whole directory (`SKILL.md` + `scaffold-bootstrap.md` + `passes/`) into `.claude/skills/audit/`. See `docs/MIGRATION.md` §1.2.1 "Optional: fork `/ft-audit` per stack" for the install workflow.
