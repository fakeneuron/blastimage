# BI-067.4 | Extract Sidebar project ⋯ menu into ProjectMenu

[← PLAN.md](../PLAN.md) · 🌱 Starter (filed 2026-10-15)

## 🌱 Starter context

_Captured 2026-10-15 during /ft-refactor survey of components/. Promote at `/ft-task BI-067.4`._

### Why this exists

The project ⋯ menu in the project header (BI-053.2 / BI-053.5) owns `menuRef`, `menuButtonRef`, and `openMenuAction`, plus the open/close and outside-click handling. It is the second self-contained piece of Sidebar.tsx. It comes after BI-067.3 so Sidebar has already shed the draft code.

### Solution shape

- New `components/ProjectMenu.tsx` owning the ⋯ button, the menu panel, its refs, and open/close with outside-click dismissal.
- Menu actions still come from Sidebar through callbacks, so the actions themselves stay where they are.
- Behavior-preserving. Sidebar's public props are unchanged. Tests from BI-067.2 and the existing suite stay green without assertion changes.
- Keep the accessible-name wiring (BI-035.3) on the menu button intact.

### Files to touch (preliminary survey — drift-check at promotion)

- `components/Sidebar.tsx` — remove menu state, refs, and the header menu JSX (~lines 135–136, 208–212, header near line 218)
- `components/ProjectMenu.tsx` — new file

### Explicitly out of scope

- Draft input — BI-067.3 (already done before this step)
- The task list, the rounds chips, and the imagegen-link block — no current plan to split these; re-survey at audit if Sidebar is still large

### Decisions locked in this conversation

| Decision | Choice | Rationale |
|---|---|---|
| Action ownership | Menu actions stay as callbacks from Sidebar | The actions are workspace operations; the menu only presents them |
| Accessible name | Preserve BI-035.3 naming on the menu button | Tests and WCAG 2.5.3 depend on it |

### Open at promotion (Phase 1 should resolve)

- Whether the outside-click listener belongs in ProjectMenu or stays in Sidebar. Lean: ProjectMenu, with the menu.
