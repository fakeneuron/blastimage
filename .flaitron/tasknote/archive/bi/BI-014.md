Friction points surfaced and resolved during dog-fooding:

1. **Remote must be pushed before submodule add** — blastimage had a GitHub remote configured but had never been pushed. `git submodule add` from the URL clones first; if the remote is empty, it fails with `fatal: You are on a branch yet to be born`. Fix: push at least one commit to origin before running submodule add. Added as the final bullet in the Prerequisites section of ADOPT.md.

2. **Stale `.git/modules/` entry after a failed attempt** — After the first failed `git submodule add` (remote was empty), git cached a partial module directory at `.git/modules/_project/blastimage/` in each parent project. A subsequent add — even with `--force` — fails because the stale dir is in the initial empty-repo state ("You are on a branch yet to be born"). And once `--force` was attempted, `blastimage/` was re-created with a dangling gitlink. Fix: `rm -rf .git/modules/_project/blastimage && rm -rf blastimage/` before retrying. Added as a Troubleshooting section in ADOPT.md.

No other friction. `npm install` in fakeneuron's `blastimage/` ran clean (2 moderate pre-existing vulns in blastimage's own deps, unrelated to adoption). Port 3003 is distinct from fakeneuron (3002) and spinalcord (4321) — no conflicts.
