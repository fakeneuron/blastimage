# BI-022.4 | cloud-images-buckets

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[BI-EPIC-022]] [[BI-022.1]] [[BI-022.3]] [[BI-022.7]]

## 🎯 Goal

Move generated + reference image **bytes** out of the Postgres rows and into a private, owner-scoped Supabase **storage bucket** in hosted mode: the adapter uploads bytes on save (re-hosting remote Grok URLs too), the DB rows reference the bucket object by path, and `loadSession` resolves each object to a short-lived **signed URL** for the existing `<img>` UI — all config-gated so local mode stays byte-identical. (The local→cloud importer is split to a new child [[BI-022.7]].)

## ✅ Acceptance

- [ ] A private `images` bucket exists (created in a migration) with owner-scoped RLS on `storage.objects` (path-prefixed by `auth.uid()`); a second operator cannot read another's objects
- [ ] `generated_images` + `ref_images` reference the bucket object via a `storage_path` column; inline-byte columns (`url` / `data_url`) no longer carry image bytes in hosted mode
- [ ] `saveSession` uploads each image's bytes once (data-URL decode **and** remote-URL re-host), keyed by image id under `{owner}/{session_id}/{image_id}`; already-uploaded objects are not re-uploaded or re-fetched on subsequent saves
- [ ] `loadSession` resolves every stored object to a signed URL placed in the domain `url` / `dataUrl`, so the review grid / gallery / reference library render unchanged
- [ ] `deleteSession` removes the session's bucket objects (no orphaned bytes for the deleted session)
- [ ] Pure mapping (`sessionToRows` / `rowsToSession` with an injected URL resolver) + data-URL decode are unit-tested; full existing suite green; `tsc` + `eslint` clean on changed files
- [ ] Local mode unaffected (adapter config-gated; localStorage still stores inline data URLs)
- [ ] Live local-stack verification: save → object in bucket → load → signed URL fetch returns bytes → cross-user storage RLS denies other operator
- [ ] Doc-drift sweep at closure

## 🧩 Subtasks

1. **Migration** (`supabase/migrations/*.sql`, additive) — create private `images` bucket; owner-scoped RLS on `storage.objects` (select/insert/update/delete `where bucket_id='images' and (storage.foldername(name))[1] = auth.uid()::text`); add `storage_path text` to `generated_images` + `ref_images`, relax `url` / `data_url` to nullable.
2. **Byte helpers** (adapter or sibling) — `dataUrlToBlob` (pure-testable) + `fetchToBlob` for remote URLs; deterministic path helper `{owner}/{session_id}/{image_id}`.
3. **Rework `sessionToRows`** — take `owner`; emit `storage_path` per image/ref (no inline bytes); keep pure.
4. **Rework `rowsToSession`** — read `storage_path`; accept an injected `resolveImageUrl(path) => string` so mapping stays pure-testable; signed-URL minting lives in `loadSession`.
5. **`saveSession` upload path** — list existing objects for `{owner}/{session_id}` once; upload only missing image ids (decode data URL or fetch+re-host remote URL), with correct contentType; then upsert/insert rows carrying `storage_path`.
6. **`loadSession` sign path** — batch `createSignedUrls` for the session's object paths; build path→URL map; pass resolver to `rowsToSession`.
7. **`deleteSession`** — remove the session's bucket folder objects (best-effort) before/after the row cascade.
8. **Tests** — update `supabaseAdapter.test.ts` (storage_path mapping + injected resolver), add `dataUrlToBlob` test; run `storage` + `useWorkspace` + `workspace` + `generate` + adapter suites; `tsc` + `eslint`.
9. **Live local-stack verify** — one-stack discipline check; `supabase start`; apply migration; throwaway test user; save/load/RLS/cross-user; then `supabase stop`.
10. **Phase 4** — doc-drift sweep, flip PLAN `.4` to stub, archive tasknote.

**Discovery Notes:**

**Single-seam reality holds.** All bucket work lives in `lib/supabaseAdapter.ts` (+ a new migration). Domain types, `useWorkspace`, and the UI are untouched: a row's `storage_path` column maps to a signed URL placed in the domain `url`/`dataUrl`; from the UI's view nothing changed.

**The re-save dedupe problem (key design point).** `saveSession` rebuilds rows from the domain `Session` every save, and after a load the domain `url` is a *signed URL* (not bytes). So format-sniffing the url to decide "upload or not" is brittle. Robust approach: list the session's existing bucket objects once per save (`storage.from('images').list('{owner}/{session_id}')`) → set of image ids already present; upload only ids **not** in that set (decoding a data URL or fetching+re-hosting a remote URL for those). This never re-uploads, never re-fetches a signed URL, and re-hosts a remote URL exactly once.

**Pure-testability.** Keep `sessionToRows`/`rowsToSession` pure by (i) passing `owner` into `sessionToRows` for path construction and (ii) injecting a `resolveImageUrl(path)=>string` into `rowsToSession`; the client-bound signing (`createSignedUrls`) lives in `loadSession` and is verified live, mirroring `.3`'s "pure mapping unit-tested + live stack for the client path" split.

**Open technical risk — provider bridge reference format.** `useWorkspace.generate()` passes `refLibrary[].dataUrl` / prior `images[].url` straight to `generateBatch` as `referenceImages`. In local mode these are data URLs; after `.4` they're signed bucket URLs. If the Grok provider bridge requires **data URLs** for references (per GROK-AGENT), generation-from-reference would break in hosted mode. This is **deferred, not solved here**: hosted-mode generation wiring is `.5`'s job (`grok-gen-cloudflare-deploy`, flagged spike-prone), and `.4` has no live generation path to regress. Logged so `.5` picks it up; not expanding `.4`'s scope.

**Implementation Notes:**

- **Migration** (`supabase/migrations/20260616010000_image_storage_buckets.sql`, additive): added `storage_path text` to `generated_images` + `ref_images`; relaxed `url`/`data_url` to nullable (bytes no longer inline in hosted mode); created the private `images` bucket (`on conflict do nothing`); one owner-scoped RLS policy on `storage.objects` for the `images` bucket (`(storage.foldername(name))[1] = auth.uid()::text`, role `authenticated`).
