**Discovery Notes:**

- Fixed columns: Sidebar 288 px + gallery rail 256 px (only after an approval, BI-054) = 544 px. At 1024 with both open, the pane is about 480 px; at 768 it would be about 224 px. That's why the floor is 1024 and not the 640 the empty view alone would allow.
- Phones out of scope: `next dev -H 127.0.0.1` (BI-058) means a phone on the LAN cannot reach the server. blastimage is a desktop authoring tool.
- No layout code changes. Below 1024 the app may still render (it does down to 640 on the empty view), but that is unsupported and unasserted.
- Spec shape: marscharts-style DOM assertions (scrollWidth vs clientWidth, bounding-box edges), no pixels. The gallery case writes (Approve → `approved/`, `selection.json`), so it uses `copyFixture` + `linkImagegenRoot` and awaits the selection POST before `afterEach` removes the copy (BI-071).

**Implementation Notes:**

- `e2e/narrow-viewport.spec.ts`: the overflow + bounding-box assertions follow marscharts' `header-narrow.spec.ts`. The writing case reuses `copyFixture` / `linkImagegenRoot` / `removeFixture` and awaits the selection POST the way `review-keyboard.spec.ts` does (BI-071). No new helper: only one spec uses the two local assertion functions.
- AGENTS.md §Stack gained a "Supported width" bullet; README §Install & Run gained one line. No source changes, no refactor.
- Mutation check: with `FLOOR` temporarily at 390, the home test failed with `Expected: <= 390, Received: 401`, matching the pilot. Restored to 1024.
- **Review-driven rework (two passes).** Pass 1: the overflow check widened from root-only to every self-scrolling pane, the bound moved from `FLOOR` to `clientWidth`, and the button sweep covers all visible buttons. Pass 2: the check now includes clipping containers (ellipsis and `sr-only` excepted), runs the full check in every state, and adds the linked pre-approve state, since Iterate and the rail never coexist.
- **Direction change (operator-confirmed).** The clip-aware check exposed a real bug: with the rail open, review cards are 129 px at 1024 and 156 px at 1280, against 181–183 px of decision-row content clipped by the card's `overflow-hidden`. Cause: `sm/lg/xl:grid-cols-*` follow the viewport, not the pane, which loses 256 px when the rail opens. Operator chose to fix it here: `ReviewGrid` and the two generating skeletons (`TaskDetail`, `BulkReviewPane`; BI-005 keeps them matching) moved to `grid-cols-[repeat(auto-fill,minmax(12rem,1fr))]`. `ReferenceLibrary`'s thumbnail grid has no controls and was left alone.
- **Grid shape revised after review pass 3.** `auto-fill` with no column cap shrank cards on wide monitors (7 tracks at 1920), and a 12rem minimum left only ~5 px over the row. Replaced with Tailwind 4 container queries on the existing wrapper: `grid-cols-1 @min-[26rem]:2 @min-[40rem]:3 @min-[54rem]:4`, with thresholds derived from a 200 px card minimum. This keeps the operator's intent (pane-relative columns) and the old 1–4 progression. Probe (deleted), chromium, cols/card px. Rail closed: 1024 → 3/219, 1232 → 4/212, 1280 → 4/224, 1440 → 4/264, 1920 → 4/384 (same as the old breakpoints). Rail open: 1024 → 2/208, 1232 → 3/203, 1280 → 3/219, 1440 → 3/272, 1920 → 4/320.

**Final Summary:**

Decided the supported width: desktop only, floor 1024 px. Phones are out of scope because the server is loopback-only. `e2e/narrow-viewport.spec.ts` (chromium + webkit) asserts at 1024 that no scrolling or clipping container overflows and every visible button is on-screen, in three states: home, linked round, and rail open.
