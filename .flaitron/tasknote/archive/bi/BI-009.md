# BI-009 | end-to-end

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-002]] [[BI-005]] [[BI-006]] [[BI-007]] [[BI-008]]

## 🎯 Goal

Wire the create→generate→review→**iterate** loop end-to-end in the workspace so a kept image carries forward into a refined next round, with no data loss (live prompt capture). Export is **re-scoped out** to [[BI-008]] (see Relevance Assessment).

## ✅ Acceptance

- [ ] A just-typed prompt that has **not** been blurred is used by Generate (no data loss; fixes BI-007's known gap)
- [ ] A **kept** image shows a per-keeper "Iterate" action that starts a new round seeded by that image as the primary reference
- [ ] The Iterate flow exposes an **editable** refined prompt, pre-filled from base prompt + the image's feedback, so the user can keep the combined prompt **or** replace it (either approach)
- [ ] The new round appends as the next iteration, renders as the latest batch, and the loop can continue from a new keeper
- [ ] `approved` images are final — no Iterate action on them
- [ ] Whole loop round-trips through localStorage (survives refresh) with no lost prompts/decisions/feedback
- [ ] `tsc --noEmit` + lint clean; unit tests for any new pure logic pass

## 🧩 Subtasks

- [ ] **No-data-loss prompt:** make `TaskDetail`'s prompt a controlled draft (keyed by task id); on Generate, pass the live draft via `onGenerate(taskId, { prompt })` and persist it via `onSetPrompt`, so an unblurred prompt is never lost
- [ ] **Iterate action (pure/hook):** confirm `useWorkspace.generate(taskId, { prompt, primaryRefImageId })` already supports the carry-forward round (BI-007) — no pure-layer change expected; if a gap surfaces, add minimal pure logic + test
- [ ] **IterateModal component:** new presentational modal mirroring `FeedbackModal` — keeper thumbnail + editable refined-prompt textarea (pre-filled base + feedback) + "Generate next round" / Cancel; Esc/backdrop/Cancel dismiss without generating
- [ ] **Wire Iterate into the grid:** add a per-keeper "Iterate" button in `ReviewGrid` (kept only; not approved); `TaskDetail`/`Workspace` open the modal and call `generate(taskId, { prompt, primaryRefImageId: image.id })`
- [ ] **Verify round-trip:** manual + (if logic added) unit coverage that the loop persists across refresh
- [ ] `tsc --noEmit` + lint clean

- [x] **Pattern survey** — looked at neighboring code for an existing pattern to extend; justified the new shape if none fits

**Implementation Notes:**

- **No pure-layer change.** The carry-forward seam (`useWorkspace.generate(taskId, { prompt, primaryRefImageId })` → `appendIteration`) already existed from BI-007. BI-009 is entirely UI wiring over it — confirms the Re-scope read that the loop's only missing rung was the iterate trigger.
- **`components/IterateModal.tsx`** (new) — mirrors the `FeedbackModal` idiom (Esc/backdrop/Cancel dismiss, callback props, foreground/background tokens). Local `composePrompt(basePrompt, feedback)` helper seeds an **editable** prompt (`base` + `Refine: <feedback>` when both present; either alone otherwise) — the user keeps the combined prompt or replaces it (either approach). Generate disabled on empty prompt.
- **`components/ReviewGrid.tsx`** — per-keeper `Iterate →` button rendered only when `decision === 'kept'` (approved = final, no button); new `onIterate(imageId)` prop threaded through `ReviewGrid` → `ReviewCard`.
- **`components/TaskDetail.tsx`** — prompt textarea is now a **controlled draft** (`promptDraft` state, resynced only on `task.id` change so an in-progress edit survives a finished round). `handleGenerate` persists the live draft via `onSetPrompt` then passes it as `onGenerate(taskId, { prompt })`, so an unblurred prompt is never lost (fixes BI-007's gap). `canGenerate` now reads the draft. `onGenerate` type widened to accept `opts`; `onIterate` threaded to `ReviewGrid`.
- **`components/Workspace.tsx`** — owns `iterateFor` open-state, resolves the keeper + its task base prompt from live session state (mirrors the `feedbackFor` pattern), renders `IterateModal`, and on submit calls `ws.generate(taskId, { prompt, primaryRefImageId })`.
- `composePrompt` is a trivial presentational helper (not `lib/` pure logic); no component unit test added, consistent with `FeedbackModal`/`ReviewGrid` (untested components; pure logic in `lib/` is where tests live).
