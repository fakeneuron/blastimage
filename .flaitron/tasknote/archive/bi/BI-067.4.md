**Discovery Notes:**

- Starter block absorbed into Goal (default); original in git history.
- [[BI-053.5]]: a local disclosure (button + panel + click-outside/Escape), deliberately **not** a shared Menu primitive and **not** `role="menu"`, because the panel holds a combobox and file-trigger buttons. Hidden file inputs must stay mounted outside the conditional panel so a closing menu cannot drop a pending picker. ProjectMenu is a named extraction of that one disclosure, not a generic primitive.
- [[BI-067.2]]: the pins cover toggle + `aria-expanded`, outside pointerdown closes, inside/⋯ pointerdown stays, Escape closes (other keys don't), every action closes and fires once, both Imports reach distinct still-connected hidden inputs, New closes and opens the draft, and the select switch closes and calls `onSwitchSession`. - [[BI-067.3]] learning: expect comment-only test diffs if a renamed symbol is named in test comments. The menu block's comments name only "BI-067.4 moves it into its own component", so no rename hits are expected.
- **Layout split (not in starter):** the ⋯ button sits in the header's flex row (L193–251), but the panel renders *after* that row and after the New-draft input (L262). It is `absolute inset-x-3` against the header `div.relative`, with no `top`, so it drops to its static position just below the flex row. One component can't own both pieces without moving the panel in the DOM. Resolved by clarification (below).
- Outside-click/Escape effect: it depends only on `menuOpen` and the two refs, so it moves with the menu (resolves the starter's open question, as leaned).
