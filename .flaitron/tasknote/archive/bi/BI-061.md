# BI-061 | link-race-ownership

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[BI-047]]

## 🎯 Goal

Make a superseded `setLinkedRoot` call lose, so a slow `/api/imagegen/link` response that resolves after a project switch or create can never re-point the live link — or bind a folder — for a project that no longer owns it.

## ✅ Acceptance

- [x] `ImagegenProvider.setLinkedRoot` is latest-call-wins: a call overtaken by a later one (including a synchronous `null` unlink) neither applies its root nor reports success; it resolves to a failure flagged `superseded` — `npx vitest run lib/ImagegenContext.test.tsx`
- [x] `linkImagegenFolder` drops its result when the call was superseded or the open project changed during the await: no binding, no rename, no round list for the stale project — `npx vitest run lib/useWorkspace.test.ts`
- [x] A superseded `syncImagegenLink` neither raises the "no longer readable" banner nor commits a legacy-root adoption over the project the operator has since opened, and leaves the legacy key for the next load — `npx vitest run lib/useWorkspace.test.ts`
- [x] Tests cover a slow `/link` resolving after a project **create** and after a project **switch** — `npx vitest run lib/useWorkspace.test.ts lib/ImagegenContext.test.tsx`
- [x] Full suite, type-check, lint clean — `npm test`, `npx tsc --noEmit`, `npm run lint`

## 🧩 Subtasks

- [x] Add a call token (ref counter) to `setLinkedRoot`; bump on every call including `null`; after the `/link` await, return `{ ok: false, error, superseded: true }` without applying when overtaken. Widen the `ImagegenApi.setLinkedRoot` return type accordingly
- [x] `linkImagegenFolder`: after the await, bail with an `error` outcome when superseded or `sessionRef.current?.id !== project.id`; guard the trailing `listRounds` set the same way
- [x] `syncImagegenLink`: suppress the unreadable-folder banner on a superseded result (legacy branch already treats `!ok` as no adoption)
- [x] Provider tests: slow link overtaken by `null`; slow link overtaken by a second link
- [x] Hook tests (gated fake modelling the provider's latest-call-wins): slow link then create; slow link then switch; slow bound-project sync then create (no banner); slow legacy adoption then create (session not flipped back)

## 🔗 Related

**Implementation Notes:**

- **Pattern:** the token is the stale-result guard this hook already uses elsewhere (the discover effect's `cancelled` flag, `sessionRef` post-await reads in generate/approve), applied at the one place that owns `rootRef`. A `useRef` counter adds no `useCallback` deps, so BI-042.4's value identity is untouched. No refactor.
- **`LinkResult`** (`lib/ImagegenContext.tsx`) = `Result<string | null>` plus a `{ ok: false; error; superseded: true }` branch. Every pre-existing `.ok` check stays correct by default — a superseded call applied nothing, so it reads as a failure — and only the two callers that must tell it apart (`syncImagegenLink`'s banner, `linkImagegenFolder`) narrow with `'superseded' in linked`. Test fakes returning a plain `Result` still typecheck.
- **`null` bumps the token too** — `createSession` / `importSessionBackup` unlink synchronously, and that is exactly the call a slow in-flight link must lose to.
- **`linkImagegenFolder`** drops on `superseded` *or* `sessionRef.current?.id !== project.id`, before the ok/owned branches, returning `status: 'error'` with a re-link hint (the picker renders it inline). The trailing `listRounds` is project-guarded the same way.
- **Tests (TDD):** 6 new — provider: unlink-overtakes-link, link-overtakes-link; hook (`racingImagegen` fake with per-path gates, token modelled as in the provider, switchable off): link-then-create, link-then-switch ×2 (with/without provider token — the second isolates the hook's own project check), bound-sync-then-create (no false banner), legacy-adoption-then-create (no flip-back). Pre-fix run: 4 failed (both provider tests, the hook-only switch case, the banner case); the create and legacy cases already passed under the token-modelling fake, so they pin the composition rather than reproduce the bug.
- With the provider token off (`latestWins=false`), the hook check protects the *binding* but not the live link — acceptable because every project-change path calls `setLinkedRoot` in the same tick it moves `sessionRef`, so with the real provider the token always fires first.
