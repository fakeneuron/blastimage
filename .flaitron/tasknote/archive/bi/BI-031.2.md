**Discovery Notes:**

**Mechanism.** Two independent silences compound. (1) `generate()`'s bare `catch {` throws away the exception before reading it, so every failure — provider absent, wrong candidate count, provider-internal error — renders as one indistinguishable sentence. (2) The two generate affordances gate only on "is there a prompt or a reference", never on "can this browser generate at all", so the plain-browser / adopter user is invited to click a button that cannot work. Fixing (1) alone would leave the user discovering the mode by failing; fixing (2) alone would leave real provider errors mute. Both are in scope.

**Clarifications asked (2), both answered with the recommended option:**

1. *Detection freshness* → **render-state probe + self-limiting poll.** The provider is installed by an agent at an arbitrary time (BI-013: install, *then* trigger generate), so a mount-only snapshot would permanently disable the buttons in exactly the session the feature is for — a false lock-out. The probe starts `false`, re-checks on an interval, and stops the interval the moment the provider appears. Deliberately **not** seeded from `useState(isGenerationAvailable)`: `Workspace` is SSR'd, and a provider present at hydration time would otherwise render server-disabled / client-enabled (hydration mismatch). Starting `false` and letting the mount effect do the first probe is both simpler and mismatch-proof.
2. *Where the reason appears* → **button `title` + the existing inline note**, not a new standing banner. `TaskDetail` already has exactly this shape for the no-prompt-no-reference case; extending it costs no new UI vocabulary, and a permanent bar would tax every adopter/viewer-mode user for a state that is normal-by-design for them.

**Scope boundary vs siblings.** [[BI-031.4]] owns rewriting `lib/generate.ts`'s BI-013-era message copy ("BI-013 live test: agent must call image_gen…") into operator-facing text — this task does **not** touch that string, it only stops discarding it. The ordering is deliberate but worth naming: between `.2` landing and `.4` landing, the developer-ish sentence is briefly user-visible in the banner. That is strictly better than the status quo (a fixed sentence that names nothing), and the disable added here makes the provider-absent path nearly unreachable by click anyway. [[BI-031.3]] owns the README/doc mode labels; the only doc touched here is `docs/GROK-AGENT.md`, and only for the behavioural note that the buttons now gate on the bridge.

**Explicit assumptions:** (1) a non-`Error` throw keeps the existing fixed sentence as fallback — the string is not deleted, only demoted; (2) the probe interval is a fixed short constant (1.5s) and is not made configurable — no consumer for a knob; (3) `generateBatch`'s own throw-if-absent guard stays, since the UI gate is advisory and `generateAll` can still race a provider that disappears; (4) `BulkReviewPane` grows no gate — it reviews an already-fired round and offers no generate affordance; (5) the iterate path (`requestNextRound`) is out of scope — BI-EPIC-024 already moved it off `generateBatch` to the terminal loop.

Discovery surfaced no significant deviation → skip 🛠️.

**Implementation Notes:**

Six source files, ~90 LOC net across code + tests.

`lib/generate.ts` — private `resolveProvider()` (the one read of the global) + exported `isGenerationAvailable()`. `generateBatch` now narrows off `resolveProvider()`, which drops its own truthiness/`typeof` pair. Its message copy is untouched — that is [[BI-031.4]]'s deliverable.

`lib/useWorkspace.ts` — `generationAvailable` state starting `false` (never read during render, so SSR and hydration agree) plus a probe effect that checks immediately, re-checks every `PROVIDER_PROBE_MS` (1500), and clears its interval for good once the bridge appears. The `generate()` catch binds the exception and surfaces `e.message`; the old fixed sentence survives only as the non-`Error` fallback.

Components — `TaskDetail` takes `generationAvailable` and computes a `generateHint` of `{ note, title }` (missing bridge outranks missing prompt/reference: no prompt helps a browser that cannot generate). `Sidebar` takes it for the ⚡ Generate All `title` so "cannot generate here" reads differently from "nothing eligible". `Workspace` folds it into `canGenerateAll` and passes it to both.

`generateBatch`'s throw-if-absent guard stays: the UI gate is advisory, and `generateAll` can still race a bridge that was never installed.
