**Discovery Notes:**

**Clarifying decisions (operator):**

1. **3-cap behavior → disable unselected at the cap.** When a task has 3 active refs, unselected thumbnails render visibly disabled/dimmed; selected thumbnails + the remove control stay interactive. The pure `toggleTaskRefImage` mutation also enforces ≤3 as a defensive no-op (UI shouldn't be the only guard).
2. **Library removal → yes, with cascade.** Each thumbnail gets a remove (×) control. `removeRefImage(session, refId)` drops it from `refLibrary` **and** clears it from every task's `activeRefImageIds` (bumping only the tasks that actually changed).
3. **Size guard → soft per-file warning.** Reject files over ~2MB (`MAX_REF_BYTES = 2 * 1024 * 1024`) before encoding, plus non-image MIME types, with an inline warning near the dropzone. The existing BI-002 quota error banner remains the backstop.

**Key design choices for execution:**

- **Pure/hook/component split mirrors BI-003.** New ref mutations are pure + React-free in `lib/workspace.ts` (unit-tested); `useWorkspace` wraps them through the existing `commit` (persist + surface `Result` error); the DOM concerns (drag-drop, `FileReader`, `Image()` decode, size/type validation) live in the new `ReferenceLibrary` component — same boundary as Sidebar owning `window.prompt`.
- **Upload warning is component-local state**, not the hook `error` (which is reserved for save failures). Capture `width`/`height` via `Image()` decode since the fields exist and feed the later export manifest.
- **Prop threading:** `TaskDetail` gains `library` + `onAddRefImage`/`onRemoveRefImage`/`onToggleRef`; `Workspace` passes `ws.session.refLibrary` + the new hook handlers.

**Exit-gate judgment:** Discovery surfaced no significant deviation — clarifications refined UX (disable-at-cap, cascade removal, size guard) within the exact placeholder-fill BI-003 anticipated; file set + approach unchanged → skip 🛠️.
