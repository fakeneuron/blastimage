# BI-034.3 | ci-audit-step

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-EPIC-034]]

## 🎯 Goal

Add an `npm audit` gate to `.github/workflows/ci.yml` that fails on genuinely new dependency advisories without failing on day one against the known Next 15 residual floor.

## ⚡ Notes

**Relevance:** Proceed — the PLAN line's premise holds exactly. `.github/workflows/ci.yml` has no audit step (checkout → setup-node → install → typecheck → lint → test → build), and `npm audit --omit=dev --audit-level=high` exited `1` at HEAD with the 4 packages BI-034.2 predicted (`nanoid`, `postcss`, `sharp`, `next`-by-association). The three-way choice the line delegates was put to the operator rather than decided unilaterally.

**Best Practices Review:** No abstraction or dependency-direction concern — one manifest block and one CI step, both declarative. The operator chose overrides-plus-strict-gate over the baseline-diff alternative, which is the outcome that adds *no* code: the rejected option needed a ~40-line script plus a committed known-bad list that would rot silently once Next 16 landed. Duplication: none. Deferred: the 2 dev-tree highs (`brace-expansion`, `js-yaml`, both under eslint/vitest tooling, both `fixAvailable: true`) are deliberately left ungated per the operator's prod-only decision — they never reach a built artifact and this app has had no deploy target since BI-028. Filing them is not warranted; the `--omit=dev` flag documents the boundary in place.

**Drift check:** No drift. `ci.yml` matched its archived description in `bi/BI-031.4.md:47`, and BI-034.2's handoff numbers reproduced exactly — 4 prod highs before, `npm audit fix` clearing none, `next@16.3.0` (`isSemVerMajor: true`) the only npm-offered fix.

**Archive skim:** `grep -rl` over `archive/{bi,core,test}/` returns one hit for `ci.yml` — `bi/BI-031.4.md`, which only *read* it to confirm nothing sets `BUILD_TARGET`; no prior tasknote has ever modified the workflow, so no precedent constrains step placement. `npm audit` returns exactly one hit, `bi/BI-034.2.md` (immediate predecessor, read in full — its §"Downstream impact on BI-034.3" scoped this task). `package.json` hits (`BI-001`, `BI-002`, `BI-021.1`, `BI-022.3`, `BI-028`, `BI-031.4`) are all dependency-add or script edits; none touched resolution behavior.

**Pattern survey:** The CI step extends the file's existing shape verbatim — a two-line `- name: / run:` pair using a bare `npm` invocation, same as the four gates above it, no action dependency introduced. The `overrides` block is a first-in-repo construct, but it is npm's own standard mechanism for exactly this case (a transitive pin the direct dependency won't move), so it is a documented-idiom addition rather than an invented shape.

**Implementation:** Two files plus the lockfile.

`package.json` — added `"overrides": { "postcss": "^8.5.26", "sharp": "^0.35.3" }`. Only two entries are needed for four advisories: `postcss@8.5.26` already depends on `nanoid@^3.3.17`, which lifts `nanoid` past its `<=3.3.16` vulnerable range transitively, and `next` was flagged only *via* `postcss`/`sharp`, so it clears once both do. Resolved tree is now `next@15.5.23 → postcss@8.5.26 → nanoid@3.3.18` and `→ sharp@0.35.3`.

⚠️ **The `postcss` override deliberately breaks Next's exact pin.** `next@15.5.23` declares `dependencies.postcss: "8.4.31"` — an exact version, not a range, i.e. Vercel pinned it on purpose. The override forces a minor bump within `8.x`. This is the one real risk in the change and it is why the full gate suite was re-run rather than assumed; `next build` produces 5 static pages / 134 kB first load, identical to the figure BI-034.2 recorded, so Tailwind's PostCSS pass is unaffected. `sharp` is `optionalDependencies` at `^0.34.3` and demonstrably unreachable here (no `next/image` anywhere; `components/ResolvedImage.tsx` renders raw `<img>`), so `0.35.3` carries effectively no risk.

`.github/workflows/ci.yml` — added an `Audit` step running `npm audit --omit=dev --audit-level=high`, **placed last, after `Build`**. Placement is deliberate: advisories arrive from the registry rather than from the diff, so a gate positioned near `Install` would let an unrelated overnight CVE mask all typecheck/lint/test/build signal on an unrelated PR. Last position keeps the functional gates reporting first and still fails the job. A three-line comment records the prod-only rationale and points at the `overrides` block, so a future reader who deletes the overrides learns why the gate then breaks.

**Verification:** `npm ci` (the actual CI install path, not just `npm install`) reproduces the overridden tree with no lockfile-sync error, and the gate exits `0`. typecheck ✅ · lint ✅ · 213 tests / 15 files ✅ · `next build` ✅ (5 static pages, 134 kB, unchanged) · `npm audit --omit=dev` → **0 vulnerabilities**, down from 4 high.

**Docs touched:** `README.md` — no change (`grep` for CI/workflow/audit finds only a `CLAUDE.md` link; no doc enumerates the CI steps). `AGENTS.md` — no change (flowtron workflow prose only). `CLAUDE.md` — no change ("Next.js 15 (App Router, TypeScript)" still accurate; the overrides don't move the framework). `.flowtron/PLAN.md` — flipped this task's line at closure.

## ✅ Recap

Closed the epic's CI gap: `npm audit --omit=dev --audit-level=high` now runs as the last step of `.github/workflows/ci.yml`, and it passes clean rather than failing on day one as BI-034.2 warned it would. Two files plus the lockfile (`ci.yml` +6, `package.json` +4, lockfile churn from the re-resolve); no source touched.

The PLAN line delegated a three-way choice — threshold, `overrides`, or baseline diff — and the operator picked `overrides` after I established that only two entries were needed. That detail is what made the option viable: `postcss@8.5.26` already requires `nanoid@^3.3.17`, and `next` was flagged only by association, so overriding `postcss` and `sharp` clears all four advisories at once. The result is a gate with real teeth (it fails on any *new* prod high) and zero custom machinery, versus the baseline-diff option's script plus a known-bad list that would have quietly rotted once Next 16 landed.

Two things a later `/ft-audit` pass should know. First, the `postcss` override overrides a **deliberate exact pin** in Next 15 (`8.4.31`), so if a future `next` patch misbehaves in the Tailwind/PostCSS path, this block is the first suspect — remove it and the gate will start failing again, which is the intended signal, not a regression. Second, when Next 16 eventually lands and fixes these upstream, **both overrides should be deleted**; leaving them pins the repo to floors it no longer needs. Neither is filed as a task since both are conditional on an upstream release the epic's Theme B explicitly won't-fixes.

Scope note: the 2 dev-tree highs (`brace-expansion`, `js-yaml`) remain ungated by the operator's prod-only decision — they sit under eslint/vitest, never reach a built artifact, and this app has had no deploy target since BI-028.

Maintainability effect: net positive. The epic's premise was that dependencies were frozen and unmonitored; the repo now has an enforced floor of zero prod advisories, and the residual Next-15 known-bads that BI-034.2 documented as an accepted floor are actually resolved rather than merely tolerated.
