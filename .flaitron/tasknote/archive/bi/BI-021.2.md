# BI-021.2 | export-folder-write

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[BI-EPIC-021]]

## 🎯 Goal

Add an "Export to folder" gallery action that writes all approved images + `manifest.json` into a user-picked directory in one step via the File System Access API, with a graceful per-image + manifest download fallback on non-Chromium browsers — restoring the provenance manifest that the painful per-image-download roundtrip caused spinalcord to bypass.

## ✅ Acceptance

- [ ] A second gallery action ("Export to folder") sits alongside "Export JSON"; appears only when there are approved images.
- [ ] On a supporting (Chromium) browser, the action prompts a directory picker and writes `manifest.json` + every approved image file into the chosen directory in one gesture.
- [ ] On a non-supporting browser, the action falls back to downloading `manifest.json` + each approved image via the existing download path (no crash, no dead button).
- [ ] User cancelling the directory picker is a silent no-op (no error surfaced).
- [ ] A write/fetch failure surfaces via the existing `UseWorkspace.error` channel rather than throwing.
- [ ] Image filenames reuse the existing `<task-slug>-<id8>.<ext>` convention; manifest is the same `buildExportManifest` JSON as `exportAll`.
- [ ] Type-checks and lints clean; targeted tests cover the new pure/branching logic.

## 🧩 Subtasks

- [ ] storage.ts: add `supportsDirectoryPicker()`, a narrow local type for the untyped `showDirectoryPicker` entry point, `exportManifestToFolder(manifest)` (picker + writes), and `downloadManifestBundle(manifest)` (fallback) — reusing `slugify`/`imageExtension`/`downloadBlob`.
- [ ] useWorkspace.ts: add async `exportToFolder()` to the hook + interface, branching on `supportsDirectoryPicker()`, surfacing failures via `setError`; cancel = no-op.
- [ ] Workspace.tsx: pass `onExportToFolder={ws.exportToFolder}` to GalleryPanel.
- [ ] GalleryPanel.tsx: add the "Export to folder" button next to "Export JSON" (shown when `approved.length > 0`), wired to the new callback.
- [ ] Tests: cover `supportsDirectoryPicker` detection, the folder-write happy path (mocked handle), cancel, and the fallback download path.
