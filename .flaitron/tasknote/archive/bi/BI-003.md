## 🎯 Goal

Build the main workspace shell — a sidebar listing the session's prompt tasks with an add-new-task control, and a detail pane for the active task showing an editable prompt, a reference-selector region, and generate controls — wired to the BI-002 persistence layer so tasks survive a refresh.

## ✅ Acceptance

- [ ] App shell renders a two-column workspace: sidebar (session switcher + task list + add-new-task) and a detail pane for the active task
- [ ] On first load with empty storage a default session is bootstrapped + persisted; on reload the active session + its tasks restore from localStorage
- [ ] Sidebar supports create / switch / rename session and add / select / rename / delete task (delete confirms)
- [ ] Detail pane shows an editable prompt (`basePrompt`) that persists, plus static placeholder regions for the reference selector (BI-004) and disabled generate controls (BI-007)

**Discovery Notes:**

**Clarifying decisions (operator):**

1. **Session model → session switcher in sidebar.** Sidebar top carries a session switcher (create / switch / rename) above the task list, using the full BI-002 multi-session API (`listSessions`/`setActiveSessionId`/`loadActiveSession`). Not the single-implicit-session form.
2. **Inner panels → static placeholder shells.** The reference-selector region (BI-004) and generate controls (BI-007) render as labeled placeholders / disabled controls. BI-003 fully owns only the prompt editor + session/task CRUD.
3. **Task controls → add + rename + delete.** Full task CRUD in the sidebar (delete confirms), plus editable task name in the detail header.

**Key design choices for execution:**

- **Pure/hook split (mirrors BI-002's serialize/DOM split).** `lib/workspace.ts` = pure, React-free, storage-free factories + immutable `Session` mutations (`newSession`/`newTask`/`addTask`/`renameTask`/`deleteTask`/`renameSession`, each bumping `updatedAt`). `lib/useWorkspace.ts` = `'use client'` hook binding the pure logic to React state + the BI-002 storage API. This keeps the non-trivial logic unit-testable **without** adding a component-test dep (`@testing-library/react`) — consistent with BI-002's "test the pure core" culture.
- **Mount-load pattern.** Workspace is a client island; it renders a neutral shell first, then `useEffect` loads `loadActiveSession()` + `listSessions()` on mount (avoids SSR/hydration mismatch on localStorage). If storage is empty, bootstrap + persist a default session.
- **Active-task selection is UI-only** — the model has no "active task" field, so it lives in hook state (not persisted). Session switch resets it to the first task.
- **IDs/timestamps:** `crypto.randomUUID()` + `new Date().toISOString()` inside the factories (browser + Node 19+; matches `ID`/`Timestamp` in the model).
- **Error surfacing:** `saveSession` returns `Result<SessionMeta>`; the hook keeps a last-error string and Workspace renders a dismissible banner on quota/unavailable failures (no throws).
- **Scope boundary:** reference selector → BI-004; generate function → BI-007; review grid → BI-005. BI-003 renders their placeholders only.

**Exit-gate judgment:** Discovery surfaced a significant scope deviation — the session-switcher and full task CRUD go beyond the literal "task list + add-new-task" line → **fire 🛠️**.

**Implementation Notes:**

- `lib/workspace.ts` — pure factories (`newSession`/`newTask`) + immutable mutations (`renameSession`/`addTask`/`deleteTask`/`renameTask`/`setTaskPrompt`); private `touch()` bumps `updatedAt`, `updateTask()` patches one task by id + bumps both stamps. `crypto.randomUUID()` + ISO timestamps inside the factories.
- `lib/useWorkspace.ts` — `'use client'` hook: mount `useEffect` restores `loadActiveSession()` or bootstraps + persists a default "My Website" session; `commit()` runs `saveSession` and surfaces `Result` errors; mutators apply the pure transforms; `switchSession` uses `loadSession` + `setActiveSessionId`. `activeTaskId` is UI-only state, reset to first task on switch/delete.
- `components/` — `Sidebar.tsx` (session `<select>` switcher + New/Rename + task list with select/✎ rename/🗑 delete + "New task"; naming via native `prompt`/`confirm` for minimal shell), `TaskDetail.tsx` (editable name input + base-prompt `<textarea>`, both uncontrolled with `key={task.id}` + persist-on-blur to avoid per-keystroke writes; dashed placeholder for references (BI-004) + disabled Generate (BI-007)), `Workspace.tsx` (owns the hook, loading shell until `ready`, dismissible red error banner, two-column flex layout).
