workspace chrome is navigable by screen reader rather than announcing bare glyphs.

**Final Summary:**

`components/Sidebar.tsx` was the one substantial component in the repo with no ARIA
naming at all — eleven `aria-label`s existed across the modals and grids, and none here.
Its two icon-only buttons announced as the bare glyphs `✎` and `🗑`, two different Import
buttons announced identically, `+ New` and `Rename` named no object, the round chips
announced as "r1", and the project `<select>` had no name whatsoever. All thirteen
buttons and the select now expose a real name.

**Changed:** `components/Sidebar.tsx` (+35 / −5) and `components/Sidebar.test.tsx`
(+93 / −5, 5 → 13 tests), plus one `.flowtron/PLAN.md` line. No import, prop, export,
dependency, or DOM restructure.

**Two design choices worth recording.** First, glyphs are neutralised by giving the
button an `aria-label` — which replaces its content for naming — rather than by wrapping
each glyph in an `aria-hidden` span. Same result, one attribute instead of a JSX shape
change per button, and it makes the empty visual diff structural rather than something
to be verified by eye. Second, every name **contains its button's visible text** (WCAG
2.5.3, Label in Name), so speech-input users can still say what they read; that is why
the chips are "Load round **r1**" and not "Load round 1". The `<select>` is the one
exception to the attribute pattern and deliberately so — a native `htmlFor`/`id`
association also makes the visible "Project" text a click target, which an `aria-label`
would not.

**Verification:** `npm test` 382 → **390 passed** / 25 files; lint and `tsc --noEmit`
clean. The load-bearing check is the mutation pass: ten names broken in turn — nine
`aria-label`s plus the `htmlFor` — every one failing on exactly the test written for it,
with the file restored and `diff -q` verified identical afterwards. That pass is not
ceremony here: an accessible name is invisible to every other assertion in the file, so
without it the new tests could be passing on markup that merely exists rather than on
names that are actually computed. The five pre-existing tests passed untouched
throughout, which is the evidence that naming the controls changed no behaviour.

**Scope.** Discovery found the PLAN line's literal reading covered 2 of 14 buttons, so
the scope was put to the operator, who chose the full chrome pass. A second finding —
the unnamed `<select>` — surfaced mid-execution and was raised at the Phase 3 confirm
rather than absorbed silently; the operator folded it in.

**Refactors:** one made (`loadRoundLabel`, so the `↻` button's visible text and its name
come from a single expression — two copies of that ternary is exactly the drift 2.5.3
describes). Two deferred with reasons: no shared label constant or map (thirteen strings
used once each; a lookup table would be indirection with no reuse), and no
`eslint-plugin-jsx-a11y` (real gap, but a lint-config change is not authorized by a PLAN
line naming one component).

**Docs:** all four AI-referenced docs swept — three unchanged with reasons, `PLAN.md`
updated. Code-facing docs updated rather than left stale: the component docstring now
records why names and `title` coexist and why the chips keep "rN", and the delete test's
comment asserting that the 🗑 glyph beats `title` in the accessible-name computation was
rewritten, since this task is what made it false.

**Maintainability:** this is a defect class that is invisible in use and invisible to
tests — the sidebar looked and behaved perfectly throughout, and the only trace of the
problem in the repo was a test that had quietly resorted to querying by `title` because
there was no name to query by. It is now pinned by eight naming tests, each proven live
by mutation, so a future edit that drops or shadows a label fails rather than silently
regressing. What is *not* fixed is the reason it happened: nothing lints for it, which is
handed to `BI-035.N` above.
