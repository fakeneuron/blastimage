# BI-037 | dependabot-actions-ecosystem

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Add a `github-actions` ecosystem entry to `.github/dependabot.yml` so the two action pins in `.github/workflows/ci.yml` stop being the repo's last unmonitored dependency class.

## ⚡ Notes

**Relevance:** Proceed — the PLAN line's premise holds exactly. `.github/dependabot.yml` declares `npm` only, and `.github/workflows/ci.yml` pins `actions/checkout@v4` (`:17`) and `actions/setup-node@v4` (`:20`), both unmonitored by anything in the repo.

**Best Practices Review:** N/A for abstraction/dependency-direction — a declarative GitHub-native config gains one list entry. Duplication: the new entry shares `directory` and `schedule` with the npm block by coincidence of both being correct, not by copy-paste of shared state; Dependabot's schema has no include mechanism, so per-ecosystem repetition is the format's own shape. Deferred: nothing.

**Drift check:** No drift. Both pins are exactly as the PLAN line (and BI-034.N's finding F2) cite them, `.github/workflows/` holds only `ci.yml`, and `.github/dependabot.yml` is byte-for-byte what BI-034.4 landed.

**Archive skim:** `grep -rl -iE "dependabot"` over `archive/*/*.md` returns two hits, both read in full during this session's BI-034.N audit. `BI-034.4.md` created the file and records the load-bearing design intent: *majors are left ungrouped so a breaking bump surfaces distinctly rather than being buried inside a grouped PR* — that intent directly shaped the grouping decision below. `BI-034.N.md` is the audit that filed this task (finding F2), and records that `.4` executed its PLAN line faithfully, so this is a cohort-level gap rather than a defect to correct.

**Pattern survey:** Extended the file's existing shape — a second `updates:` list entry using the same `package-ecosystem` / `directory` / `schedule` triple as the npm block, per GitHub's standard `version: 2` schema. **Deliberately did *not* mirror the npm block's `groups:` key.** Both pins are major tags (`@v4`), so essentially every update Dependabot raises for this ecosystem is a major version bump, which is individual-PR by default; a `patch-and-minor` group would be config that never fires, and it would blur the very distinction BI-034.4 designed for. Symmetry with the npm block would have been cosmetic, so minimalism won and the reasoning is recorded inline as a comment rather than left for a future reader to re-derive.

**Implementation:** One entry appended to `.github/dependabot.yml` — `package-ecosystem: "github-actions"`, `directory: "/"` (which for this ecosystem means `.github/workflows`, not the repo root's manifests), `schedule.interval: "weekly"` matching the npm cadence. A three-line comment above it records the directory semantics and the ungrouped rationale, mirroring the comment style BI-034.3 established above the `Audit` step in `ci.yml`. Verified by parsing to the expected two-entry `updates` array.

**Docs touched:** `README.md` — **updated.** The dependency-tooling paragraph added by BI-034.N read "weekly npm PRs with patch/minor grouped and majors raised individually", which this change makes incomplete; now reads "weekly npm and GitHub Actions PRs, with npm patch/minor grouped and majors raised individually" — the qualifier moved onto `npm` because the grouping is npm-only by design. `AGENTS.md` — no change (flowtron workflow prose; documents no dependency policy). `CLAUDE.md` — no change (Stack section covers framework/state/target API/dev port/testing; CI tooling is none of those and README carries it). `.flowtron/PLAN.md` — flipped this task's line at closure.

## ✅ Recap

Closed the last gap BI-EPIC-034 left open. `.github/dependabot.yml` gained a `github-actions` ecosystem entry (weekly, root — which for this ecosystem resolves to `.github/workflows`), so `actions/checkout@v4` and `actions/setup-node@v4` are now monitored like every other dependency in the repo. Two files: the config (+8 including comment) and a one-clause README correction. No code touched.

The one real decision was **not** copying the npm block's `groups:` key. Both action pins are major tags (`@v4`), so nearly every update Dependabot raises here is a major and lands as its own PR anyway — a `patch-and-minor` group would be config that never fires, and grouping would work against BI-034.4's explicit intent that breaking bumps surface distinctly. That reasoning is recorded as a comment in the file itself so a future reader doesn't "fix" the asymmetry.

One thing a later `/ft-audit` pass should know: the `directory: "/"` on this entry does **not** mean the repo root the way it does on the npm entry above it — for `github-actions` it means `.github/workflows`. The two entries look parallel and are not; the inline comment says so.

Verification: `.github/dependabot.yml` parses to the expected two-entry `updates` array. Gates run as regression on a config-only change — typecheck ✅ · lint ✅ · 213 tests / 15 files ✅ · `npm audit --omit=dev --audit-level=high` → 0 vulnerabilities ✅. The entry's real behavior is only observable once GitHub next runs Dependabot against the repo.

Maintainability effect: BI-EPIC-034's theme ("Dependencies are frozen, not managed") now holds for every dependency class in the repo rather than for npm alone.
