### Findings

**F1 — `lib/generate.ts`'s own comments still narrate the BI-013 one-off live test as the present operating mode.** The epic fixed the user-facing string but not the code-facing prose wrapped around it. Four spots: the `GrokImagineProvider` doc (`:57-59`, "For this live test the agent orchestrates…"), the `declare global` comment (`:64-66`, "during BI-013 live test (and future transparent runs inside Grok Build)" — that future is now the present), `generateBatch`'s JSDoc (`:92-93`, "during a pure-client test run"), and the block above the throw (`:110-114`, "During this agent-driven live test the caller (**the /ft-task driver**) is expected to pre-produce real images…"). BI-031.4 consciously scoped these out (its assumption 2: developer-facing architecture notes, surgical-edit convention) — a defensible per-task call, but it leaves mode-confusion residue in the exact file the epic was about. **Actionable.**

**F2 — paperwork: `BI-031.3` and `BI-031.4` archived with every `## ✅ Acceptance` and `## 🧩 Subtasks` box unticked.** Both have all Phase 1-4 boxes ticked and complete Final Summaries, and the work genuinely landed — the spec sections were simply never back-ticked at closure, against `SPEC.md` §"🚀 Phase 4: Closure" ("never leave a box silently unticked"). `BI-031.2` did it correctly, so this is drift between same-day sessions, not a misread of the contract. **Recorded, not fixed** — archived tasknotes are write-once historical records.

**F3 — the provider probe polls forever in the common case (considered, accepted).** `useWorkspace.ts:298-306` re-probes every 1.5s and clears the interval only once the bridge appears — which in adopter / plain-browser mode never happens, so the timer runs for the session's life. Assessed and accepted: the work per tick is a single property read, browsers throttle background-tab intervals anyway, and any bounded retry would reintroduce exactly the false lock-out BI-031.2 designed the probe to avoid (BI-013 installs the bridge at an arbitrary post-load moment). **No action.**

**F4 — the missing `.1` slot is unexplained in PLAN.md (cosmetic).** See the Discovery numbering note. The parent line does record "Discovery supplied by audit-repo 2026-08-06", which is the explanation — just not adjacent to the numbering. **No action.**
