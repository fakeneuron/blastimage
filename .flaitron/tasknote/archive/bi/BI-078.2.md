**Implementation Notes:**

- **Pattern.** `clip` follows the `ref` path exactly: optional field on `RoundBatchTask` and `TerminalTaskPlan`, validated in `parseRoundBatch`, copied in `buildRoundBatch`, omitted (never `undefined`) when absent per `exactOptionalPropertyTypes`. `parseClip` returns the repo's `Result<T>` so the typed value comes out of validation, not a second untyped read. `TERMINAL_CLIP_TAKES` sits beside `TERMINAL_BATCH_SIZE` with the same `as const` form; its test sits beside BI-065's pin.
- **Refactor gate.** Only the stale `RoundSummary` comment (assigned here by BI-078.1). Nothing else touched.
- **Fixture.** `test-fixtures/imagegen-clip/`: `approved/hero-banner-002.jpg` (320×180 JPEG, ffmpeg `testsrc2`), `rounds/r1/hero-banner-00{1,2}.mp4` (2 s, 12 fps, H.264 High, `yuv420p`, `-an`, `+faststart`, CRF 32; take 2 hue-shifted 120° so the bytes differ), and `batch.json` with `ref: approved/hero-banner-002.jpg` and `clip.durationSeconds: 2` (the real length, not the 6 s default). ~48 KB binary total. A clip approved from this root lands on `approved/hero-banner-00N.mp4`, beside the `.jpg` still without a name clash.
- **Fixture test.** A vitest case reads the fixture: it parses, each `ref` and take exists, takes read as `video`, and each take starts with an `ftyp` box. ffprobe is a Phase 3 receipt, not a test, so `npm test` does not need ffmpeg on CI.
- **After the External review** (Phase 3) the parser also enforces that a task carrying `clip` has an `approved/` ref and only `.mp4` takes, and rejects an array `clip`. The fixture moved its file read inside the tests. See Testing Notes.
- **For BI-078.3–.5:** link or copy `test-fixtures/imagegen-clip/` (TEST-008's copy-then-link helper hard-codes the still root, so a writing spec needs a variant). Call `mediaKindFromPath` on the stored `imagegen:` URL, not on a display URL: `imagegenFileUrl` appends `&v=<epoch>`.

**External review** — `/code-review medium` over this task's working-tree diff only (fixture files intent-to-added so they appeared in it). No blockers; eight notes:

1. A clip round parses before BI-078.3 can serve `.mp4`, so it would show broken images. **Accepted as sequencing**: nothing writes a clip round until BI-078.6; REVIEW-LOOP says serving arrives with .3–.6.
2. `clip` and the file extensions could disagree. **Fixed**: a task with `clip` must have only `.mp4` takes.
3. `clip: []` passed the object check. **Fixed**: arrays rejected; test added.
4. A clip task's `ref` was not checked. **Fixed**: a task with `clip` must have a `ref` under `approved/`. `.mp4` takes without `clip` still parse (provenance stays optional).
5. `mediaKindFromPath` misreads a URL with a query or fragment; `.mov`/`.webm` read as image. **Fixed in the doc comment** (pass the stored path, never an `imagegenFileUrl` display URL, whose `&v=` hides the extension); `.mp4`-only is the BI-078.1 decision.
6. The fixture describe read the file at collection time. **Fixed**: read inside each test.
7. Clip takes are counted and labelled as images. **Parse error text fixed** ("image or clip filename"). The Sidebar round chip's "N images" label is outside `touches:`: **filed** as BI-085.
