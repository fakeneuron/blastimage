## 🎯 Goal

A `selection.json` write can neither lose a concurrent decision, leave a torn file, nor persist content the reader will later reject; and `filenameFrom` refuses the `.`/`..` path segments.

## 📝 Phase 1: Discovery

- [x] Reviewed the task entry in PLAN.md

- [x] **Relevance Assessment**

  **Verdict:** Proceed
  **Rationale:** All three defects are live at HEAD (see Drift check). The route writes whatever `tasks` array it is handed; a malformed entry or a blank `selectedAt` persists a file that `readRoundSelection` then rejects, and because `writeRoundSelection` reads-before-writing, every later write to that round fails too — the round's inbox is bricked until someone hand-edits the file. The unserialized read-merge-write loses decisions when two posts overlap (`Promise.all` in-process reproduces it).

- [x] Read relevant source files — `lib/imagegenServerFs.ts`, `lib/roundSelection.ts`, `lib/imagegenRoute.ts`, `app/api/imagegen/selection/route.ts`, `app/api/imagegen/approved/route.ts`, and the tests `lib/imagegenServerFs.test.ts`, `lib/imagegenRoute.test.ts`, `lib/roundSelection.test.ts`, `lib/imagegenRouteGuard.test.ts`, `vitest.config.mts`

- [x] **Best Practices Review** — Responsibilities stay where they are: validation is in the pure `roundSelection` module, bytes are in `imagegenServerFs`, and HTTP translation is in the route and `imagegenRoute`. Dependencies still point route → lib, pure ← fs. The one refactor is extracting the per-entry parser out of `parseRoundSelection`'s loop. It is required, because Acceptance asks for a shared parser, and it removes what would otherwise be a second copy of the rules in the route. The per-path lock stays module-private in `imagegenServerFs`; it has one caller, so no general mutex utility.

  No clarifications needed (--fast). Assumptions:
  1. The per-entry parser keeps `parseRoundSelection`'s current semantics exactly: slug/keeper/nextPrompt trimmed, invalid optional fields dropped, and no new "keeper required for iterate/approve" rule. Tightening the reader would reject files already on disk and is out of scope.
  2. "Serialize per file path" means an in-process promise chain keyed by the resolved target path. The Next server is the only writer of `selection.json`; the terminal skill reads it. Cross-process exclusion is out of scope, but tmp + rename still means a terminal reader never sees a torn file.

  4. Route-handler tests live in `lib/` (the vitest glob excludes `app/`) and import the handler through the `@/` alias, the same placement rationale as `lib/imagegenRouteGuard.test.ts`.

**Discovery Notes:**

- `..` today: `DELETE /api/imagegen/approved?filename=..` resolves `approved/..` to the root itself. Confinement allows it (`target === root`), and `unlink(root)` then fails with EISDIR/EPERM, so nothing is destroyed. The fix is still defense in depth: a filename that names a directory should never reach `fs`.
- A malformed file bricks the round because of the read-first write path. That makes the route-side validation more than hygiene.

**Implementation Notes:**

- `lib/imagegenServerFs.ts` — `serializedByPath` chains writes on the resolved target path, runs on both fulfilment and rejection of the predecessor, and deletes the map entry when it is the tail, so the map doesn't grow. `writeRoundSelection` now resolves the target before taking the lock, then runs read → merge → write to `<target>.<pid>.<uuid>.tmp` → `rename`. On failure it removes the temp file best effort. The temp file is a sibling of the already-confined target, so it needs no separate confinement check.
- `lib/roundSelection.ts` — exported `parseRoundSelectionTask(entry, index)`; `parseRoundSelection` calls it per entry. Semantics are unchanged (assumption 1).
- `app/api/imagegen/selection/route.ts` — `selectedAt` must be non-blank, and every task goes through `parseRoundSelectionTask`. The first bad entry returns its 400 message and nothing is written. The parsed (normalized) tasks are what get written, which replaces the old `as RoundSelectionTask[]` cast.
- `lib/imagegenRoute.ts` — `filenameFrom` rejects an exact `.`/`..` with the existing separator message. Names that merely contain dots still pass.
- Red-first evidence: the concurrent-write test failed at HEAD (5 of 6 slugs lost); the route test failed 5/7 against the HEAD route (restored after).
